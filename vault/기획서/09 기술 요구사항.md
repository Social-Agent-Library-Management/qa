# 3. 기술 요구사항 (검색·이벤트)

> 배치·알림(3.1)은 [[06 알림]] 참고.

## 3.2 도서 검색을 위한 OpenSearch
- **목적**: 도서 수 증가에 따른 RDBMS `LIKE` 검색의 한계(성능·정확도) 개선
- **전략**: 도서 서지 정보를 OpenSearch에 인덱싱해 전문 검색 제공
- **주요 기능**: 한글 형태소 분석 기반 자연어 검색(예: `클린` → `클린 코드`·`클린 아키텍처`), 초성 검색, 오타 보정(fuzzy), 도서 등록/수정 시 인덱스 동기화(3.3과 연계)
- **설계 의도**: 조회 책임을 검색 엔진으로 분리(CQRS 관점). RDBMS는 정합성, OpenSearch는 검색 최적화에 집중.
- **구조**: `BookSearchPort` 인터페이스로 포트/어댑터 구조. `search.engine` 설정 값으로 어댑터를 전환한다.

## 3.3 이벤트 기반 아키텍처 (EDA)
- **목적**: 원본(RDBMS)과 검색 인덱스(OpenSearch) 간 동기화를 등록/수정 로직과 결합하지 않고 느슨하게 처리
- **채택안**: 애플리케이션 이벤트 발행 (`@TransactionalEventListener(AFTER_COMMIT)` + 비동기). 검색 반영은 결과적 일관성 허용.

| 방식 | 평가 | 판단 |
|---|---|---|
| 이중 쓰기 (Dual Write) | 부분 실패 시 정합성이 깨질 수 있음 | ❌ 지양 |
| **애플리케이션 이벤트 발행** | 구현이 단순하고 트랜잭션과 자연스럽게 연계 | ✅ MVP 채택 |
| CDC 기반 이벤트 발행 | 정합성 강력, 인프라 운영 부담 | 🔮 대규모 확장 시 |
| 주기적 배치 | 실시간성 낮지만 유실·정합성 보정에 유용 | ➕ 보정용 병행 |

> ⚠️ 이 노트의 "구현 상태" 서술은 기획서 작성 시점 기준이다. 이후 백엔드에 OpenSearch 어댑터·이벤트 색인·outbox 재시도·RDB 대체 조회가 구현되었다(백엔드 이력 #43~#56 참고). 판정은 최신 이력을 우선한다.
