# 2.5 연체 관리 (Overdue) — ⭐ 핵심 가치

프로젝트의 두 번째 동기('연체 도서 추적 불가')를 정면으로 해결하는 기능.

- **[MVP] 연체 판정** — **반납 예정일 익일부터 즉시 연체**로 확정 (유예 기간 없음). 아직 반납되지 않은 대출 건이 대상.
- **[MVP] 연체 목록 조회** — **별도 화면을 두지 않고** 대출 내역 조회에서 상태 필터 `연체`로 확인한다. **대시보드에는 연체 건수 통계와 경과일 내림차순 D-day 목록(대출자·부서·반납예정일)을 요약으로 유지**.
- **[고도화] 연체 통계** — 부서별·기간별 연체 현황 집계 (미구현)

## 설계 노트 — 연체는 저장하지 않고 '파생 계산'한다
연체는 시간이 지나면 자동으로 성립하는 상태다. 별도 컬럼에 저장하면 실제 시점과 어긋나고 동기화 배치가 필요해진다. 그래서 연체 상태를 저장하지 않고 **조회 시점의 날짜로 계산**한다. (`Loan`의 `isOverdue()`/`currentOverdueDays()`/`overdueDays()`가 이 원칙대로 구현되어 있다.)

- **Loan에 저장하는 것**: 반납 예정일(`dueDate`), 반납일(`returnedAt`), 대출 상태 `대출중 / 반납완료`
- **현재 연체 여부** = `대출중 AND 반납예정일 < 오늘` → 조회 조건으로 계산
- **반납 지연 여부 / 지연 일수** = `반납일 > 반납예정일`, `반납일 − 반납예정일` → 저장된 값으로 도출되므로 별도 저장하지 않음
- 알림 배치는 연체 상태를 '만드는' 것이 아니라, 날짜 조건에 맞는 대출 건을 '찾아' 알림을 보낼 뿐이다.
- (예외) 수백만 건 규모에서 연체일수 정렬·집계 성능이 문제될 때만 비정규화 저장을 고려한다.
