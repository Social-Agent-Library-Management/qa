# 프로젝트 개요

## 시작 계기
사회복무요원으로 근무하며 맡은 "교육 준비 및 도서관 책 관리" 업무에서 도서 대출을 수기로 작성·보관해 다음 불편이 있었다.

- **수기 검색의 번거로움**: 반납할 때마다 대출 기록부를 뒤져 내역을 찾아야 했다.
- **연체 도서 추적 불가**: 작년에 대출된 책이 반납되지 않았는데도 확인·추적이 어려웠다.
- **기록 누락·데이터 불일치**: 반납 요청이 왔지만 기록부에 대출 내역이 없는 경우가 있었다.

단순 학습용을 넘어 실제 근무 환경을 개선하기 위한 프로젝트다. 백엔드는 Java 경험을 Kotlin으로 확장하기 위해 선택했다(null 안정성, data class, sealed class).

## 시스템 개요
관리자가 기관 내 도서의 **대출·반납·연체 상태**를 추적·관리하는 서비스. 알림 자동화와 검색 최적화로 사용성과 성능을 확보하는 것이 목표.

- **주 사용자**: 관리자(사회복무요원) 단일 계정 — 인증 필요 (현재 MVP 코드에는 인증 미구현)
- **핵심 가치**: ① 수기 검색 → 즉시 조회 ② 연체 도서 자동 추적 ③ 데이터 정합성 보장

## 도메인 모델
| 엔티티 | 설명 | 관계 |
|---|---|---|
| Book (도서) | 서지 정보 단위 (도서명·저자·출판사·ISBN) | 1 : N BookItem |
| BookItem (소장본) | 실제 물리적 보유본. 관리번호·대출 상태 보유 | 1 : N Loan |
| Loan (대출) | 소장본 1건의 대출~반납 이력 | N : 1 BookItem |

> **핵심 구분**: 도서(Book)는 정보, 소장본(BookItem)은 실물. 같은 책 3권 = Book 1 + BookItem 3. **대출/반납/상태는 항상 BookItem 단위**로 처리한다.
