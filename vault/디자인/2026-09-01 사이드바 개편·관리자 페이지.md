# 디자인 스펙 — 사이드바 개편 & 관리자 페이지(탭 허브) 신설

디자인 소스: Claude Design "도서 관리 시스템 Design System" (`307f4357-35a5-463d-9674-9b2fefff09fa`)
- `components/navigation/Sidebar.jsx` — `SIDEBAR_NAV_ITEMS`(5개) / `ADMIN_NAV_ITEMS`(5개) / 아이콘 3종 신규
- `ui_kits/library/index.html` L745-825 — `ADMIN_ITEMS` / `AdminTabsLayout` / `App`(라우팅 폴백 로직)
- 입력 형태: 내보낸 React 코드(정확). 이슈 #31, 브랜치 `feat/#31`.

## 개요

기존 사이드바 최상위 nav 7개 중 3개(도서 등록/소장본 등록/대출 내역 조회)를 제거하고, 그 자리를 대체하는 **관리자 페이지** 허브 nav 항목 1개를 추가한다. 관리자 페이지는 상단에 지속되는 **탭 바**를 가진 하위 화면 묶음이며, 제거된 3개 화면이 탭으로 이동하고 신규 탭 2개(엑셀 일괄 등록/내보내기, 이번 범위에서는 플레이스홀더)가 추가된다. 기존 3개 화면의 폼/목록/API 로직 자체는 변경하지 않는다 — 라우트 위치와 진입 경로(nav)만 바뀐다.

## 디자인 토큰

기존 프로젝트 `@theme` 토큰과 100% 매핑된다 — 신규 토큰 없음.

| 디자인 원문 (`var(--color-*)`) | 프로젝트 토큰 |
|---|---|
| `--color-primary` (활성 탭/nav 텍스트) | `text-primary` |
| `--color-primary-light` (활성 nav 배경) | `bg-primary-light` |
| `--color-text-primary` | `text-fg` |
| `--color-text-secondary` (비활성 탭) | `text-fg-muted` |
| `--color-border` | `border-line` |
| `--color-surface` (탭 바 배경) | `bg-surface` |

탭 바 스펙(디자인 `AdminTabsLayout` 인라인 스타일 → 토큰/유틸 매핑):
- 컨테이너: `bg-surface`, 하단 `border-b border-line`, 좌우 패딩(디자인 `0 40px`) — 페이지 여백은 `layout.tsx`의 `<main>`이 이미 `px-page-x`로 소유하므로 탭 바는 **`main` 여백 안에서 자체 마이너스 마진 없이** 렌더(디자인처럼 별도 40px을 다시 주지 않는다). `gap-1`(디자인 `gap:4`)
- 탭 버튼: `py-[11px] px-4 text-body`, active `font-semibold text-primary border-b-2 border-primary`, inactive `font-normal text-fg-muted hover:text-fg`, `-mb-px`로 컨테이너 보더와 겹침(디자인 `marginBottom:-1`)
- 기존 `nav-item` 관련 cva/토큰(`rounded-button`, `focus-ring` 등)은 사이드바 nav item 스타일이지 탭과 무관 — 탭은 밑줄(underline) 스타일이므로 새 variant 축으로 설계 필요(컴포넌트 아키텍트 판단)

## 상태 & 상호작용

- **사이드바 활성 판정**: `/admin` 하위 어떤 경로에 있어도(`/admin/books/new`, `/admin/excel-import` 등) 사이드바에서는 "관리자 페이지" 1개만 활성 강조된다(디자인 `inAdmin ? 'admin' : screen`과 동일 원칙). `resolveActiveNavId`는 이미 최장 접두 매칭을 지원하므로 `nav-items.tsx`에 `{ id: "admin", href: "/admin" }`를 등록하면 `/admin/books/new` 등에서 접두 매칭으로 자동 해결될 것으로 보임 — **구현 시 반드시 확인**(미확정, 아래 참조).
- **탭 활성 판정**: 탭 바는 현재 하위 경로(`/admin/books/new` 등)와 정확히 일치하는 탭만 활성. `/admin` 루트 자체는 미확정 상태 — 아래 참조.
- **탭 클릭**: `<Link>` 네비게이션(디자인은 SPA `onNavigate` state 전환이지만, Next.js에서는 실제 라우트 전환 — `Sidebar`의 nav item과 동일하게 `href` 기반 `<Link>`로 구현).
- **엑셀 일괄 등록/내보내기 탭**: 클릭 가능하고 탭 자체는 정상 렌더되지만, 콘텐츠는 `PagePlaceholder`(준비 중 안내) — 업로드/다운로드 등 실제 인터랙션 없음(범위 밖).
- hover/focus 상태: 탭 버튼은 사이드바 nav item과 동일하게 `focus-ring` 유틸 적용, hover는 텍스트 색 전환(디자인 `hover: color text-primary`) — 배경색 hover는 없음(사이드바 nav item과 다른 점, 디자인 원문 그대로).

## 반응형 규칙

디자인 프로토타입은 데스크톱 전용(1440×900, 사이드바 260px 고정)이며 이 프로젝트의 기존 화면들도 반응형 분기를 별도로 두지 않는다(`layout.tsx`가 이미 `sm:px-page-x` 정도만 사용). 관리자 탭 바도 동일 기준 — **별도 반응형 규칙 없음**, 기존 페이지 컨벤션을 따른다.

## 데이터/콘텐츠 형태

```ts
// nav-items.tsx 확장 (신규 필드 없음, 기존 LibraryNavItem 재사용)
LIBRARY_NAV_ITEMS: LibraryNavItem[]  // 5개로 축소, "admin" 항목 추가

// 신규
interface AdminTabItem {
  id: string;
  label: string;
  href: string;       // "/admin/books/new" 등
  Icon?: React.ComponentType<IconProps>;  // 디자인엔 탭 아이콘 없음(사이드바 서브 nav에만 아이콘) — 탭 바 자체는 텍스트만
}
ADMIN_TAB_ITEMS: AdminTabItem[]  // 5개, 순서: 도서 등록 → 소장본 등록 → 대출 내역 조회 → 엑셀 일괄 등록 → 내보내기
```

## 미확정 항목 (사용자 확인 완료 / 구현 시 재확인 필요)

1. **라우트 이동 범위** — 사용자 확인 완료: `/books/new`→`/admin/books/new`, `/copies/new`→`/admin/copies/new`, `/loans/history`→`/admin/loans/history`. 기존 URL 리다이렉트는 만들지 않는다(외부 공유 링크 없음, 사이드바가 유일한 진입점).
2. **신규 탭 2개 범위** — 사용자 확인 완료: `PagePlaceholder`로만 추가, API 연동 없음.
3. **`/admin` 루트 자체의 동작** — 디자인은 `screen==='admin'`일 때 `adminId` 폴백으로 첫 탭(도서 등록)을 보여준다. Next.js 구현에서는 (a) `/admin`을 `/admin/books/new`로 서버 리다이렉트하거나 (b) `/admin/page.tsx`가 `BookRegisterSection`을 직접 렌더 — 아키텍트가 라우트 구조 결정 시 선택. **리다이렉트 방식을 권장**(URL이 항상 실제 탭을 가리켜 새로고침·공유 시 일관됨).
4. **탭 바 아이콘 유무** — 디자인 `AdminTabsLayout`은 아이콘 없이 텍스트만(사이드바 서브 nav 아이템에는 아이콘이 있지만 그건 다른 컴포넌트). 탭에는 아이콘을 넣지 않는다.
5. **`IconAdmin`/`IconImport`/`IconExport`의 정확한 stroke path**는 `components/navigation/Sidebar.jsx` 원문(위 인용)을 그대로 이식하되, 프로젝트의 `IconBase`(`stroke="currentColor"`, `size` prop) 패턴에 맞춰 좌표를 그대로 재사용한다.
