# 디자인 스펙 — 도서 검색 오타 교정 제안

디자인 소스: Claude Design "도서 관리 시스템 Design System" > `ui_kits/library/index.html` > `BookSearchScreen`(검색 결과 `DataTable`의 `emptyText`)

## 대상 위치

기존 화면(#23으로 이미 구현됨) `/book-search`의 좌측 카드 — 현재 구현: `src/components/library/book-search-result-card.tsx`(`BookSearchResultCard`), 그 안의 `DataTable`의 `emptyText` prop.

새 화면이 아니라 **기존 컴포넌트의 빈 상태(empty state) 분기 추가**다.

## 상태 정의

검색 결과 `DataTable`의 `emptyText`는 두 가지로 갈린다:

1. **suggestion 없음** (기존 동작 유지) — 단순 텍스트 "검색 결과가 없습니다."
2. **suggestion 있음** (신규) — 아래 3단 레이아웃, 가운데 정렬

```
검색 결과가 없습니다.

혹시 "가족복지론"을 찾으셨나요?

[ 가족복지론(으)로 다시 검색 ]  ← ghost 버튼, size sm
```

## 디자인 원문 (참고용 JSX, 그대로 이식하지 않음 — 아래 "재사용 매핑" 참조)

```jsx
emptyText={suggestion ? (
  <div style={{textAlign:'center'}}>
    <div>검색 결과가 없습니다.</div>
    <div style={{marginTop:14,fontSize:13,color:'var(--color-text-secondary)'}}>
      혹시 <b style={{color:'var(--color-text-primary)',fontWeight:600}}>"{suggestion}"</b>
      {withEul(suggestion).slice(suggestion.length)} 찾으셨나요?
    </div>
    <Button variant="ghost" size="sm" style={{marginTop:10}}
      onClick={()=>{setSearch(suggestion);setSelected(null);}}>
      {withEuro(suggestion)} 다시 검색
    </Button>
  </div>
) : "검색 결과가 없습니다."}
```

한국어 조사 처리 헬퍼(디자인 원문, 동일 로직 필요):

```js
const hasBatchim = ch => (ch.charCodeAt(0) - 0xAC00) % 28 !== 0;
const withEul  = w => w + (hasBatchim(w[w.length-1]) ? '을' : '를');   // 을/를
const withEuro = w => w + (hasBatchim(w[w.length-1]) ? '으로' : '로'); // 으로/로
```

## 재사용 매핑 (design → 코드베이스 프리미티브)

- 문구 텍스트 `<div>` → 인라인 마크업 유지(1회용, Tailwind 유틸리티 클래스로 변환. `var(--color-text-secondary)` → 기존 토큰 클래스 확인 필요 — `text-text-secondary` 등 프로젝트 관례를 따를 것)
- `<Button variant="ghost" size="sm">` → 기존 `@/components/ui/button`의 `Button` 그대로 재사용(신규 variant 불필요)
- 조사 헬퍼(`hasBatchim`/`withEul`/`withEuro`) → 다른 컴포넌트에서 쓰이지 않는 1회용이므로 `book-search-result-card.tsx` 파일 내부에 인라인(README 원칙: "2회 반복이면 추출, 1회용은 인라인"). 새 `lib/` 파일 만들지 말 것.

## 상태/상호작용

- 트리거 조건: `rows.length === 0 && !loading && !error && result?.suggestion` (참고: 기존 코드의 `loading`/`error`/`rows`/`result` 파생 변수 그대로 사용)
- `suggestion`이 `null`이면 완전히 기존 동작(빈 텍스트만) — **아무 것도 새로 렌더링하지 않는다**(사용자 확정 사항)
- 재검색 버튼 클릭 시: 검색어를 `suggestion`으로 교체해야 함. 단, `BookSearchResultCard`는 `query`를 prop으로만 받고 소유하지 않는다(`BookSearchSection`이 소유) → **새 콜백 prop 필요**: `onSuggestionSearch?: (term: string) => void` 형태로 부모(`BookSearchSection`)에 위임. 부모는 기존 `handleReset`과 동일한 패턴으로 `setSearch(term); setSelected(null);` 수행.

## 데이터 shape 변경

`src/lib/api/books.ts`의 `BookSearchResult` 타입에 `suggestion: string | null` 필드 추가 (백엔드 `SearchBooksService.Response.suggestion` 1:1 매핑, `@Schema` 설명: "검색 결과가 0건일 때, 오타 교정 제안어(없으면 null)").

## 반응형/접근성

- 별도 반응형 규칙 없음(기존 emptyText 셀 안에서 렌더, `DataTable`의 기존 반응형에 종속)
- 버튼은 텍스트 라벨을 그대로 포함하므로 별도 aria-label 불필요
