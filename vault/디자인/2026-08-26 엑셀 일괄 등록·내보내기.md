# 디자인 스펙: 엑셀 일괄 등록 / 내보내기 (issue #27)

## 개요

Library 관리 시스템에 새 화면 2개를 추가한다.

1. **엑셀 일괄 등록** (`ExcelImportScreen`) — 하나의 `.xlsx`/`.xls` 파일을 업로드해 도서와 소장본을 한 번에 등록한다. 서버는 `POST /imports/excel`을 **동기·all-or-nothing**으로 처리하며, HTTP 상태(201/409)로 성공/거부를 구분한다.
2. **내보내기** (`DataExportScreen`) — 저장된 도서/소장본/대여 데이터를 시트 3개짜리 엑셀 파일로 즉시 다운로드한다. `POST /exports/excel`은 JSON 요청 → **바이너리(Blob) 응답**이다.

두 화면 모두 입력 소스는 Claude Design 내보낸 JSX(`_workspace/00_input/design-ui-kit-library.html`, `ExcelImportScreen`/`DataExportScreen`만 발췌)이며, 실제 데이터 계약은 리더가 백엔드(Kotlin)를 읽고 정리한 `_workspace/00_input/api-notes.md`가 **단일 진실 원천**이다. 디자인 목업의 코드값·컬럼·행수는 곳곳에서 실제 API와 다르며, 이 스펙은 실제 API를 기준으로 작성했다(불일치 지점은 각 섹션에 명시).

두 화면 모두 기존 `apiFetch`(JSON 전용)로 호출할 수 없는 엔드포인트다 — multipart 요청(등록)과 Blob 응답(내보내기) 각각에 전용 fetch 함수가 필요하다. 이는 데이터 shape 섹션에 상세 기술한다.

## 레이아웃 트리

### 1) 엑셀 일괄 등록 (`ExcelImportScreen` → 가칭 라우트 `/imports/excel`, 실제 경로는 `nav-items.tsx` 신설 시 확정)

```
Page (padding: page 표준 여백 — layout.tsx <main> 소유, 화면에서 재정의 안 함)
├─ PageHeader (title="엑셀 일괄 등록", description="하나의 엑셀 파일로 도서와 소장본을 함께 등록합니다")
│
├─ [phase: idle | picked | uploading] 공통 블록
│  ├─ Card (title="엑셀 파일")
│  │  ├─ [phase=idle] 파일 선택 영역
│  │  │  ├─ 드롭존 (점선 테두리, radius lg, 안내 텍스트 2줄: "파일을 끌어다 놓거나 아래에서 선택하세요" / ".xlsx · .xls · 최대 20MB · 첫 행은 머리글로 처리됩니다")
│  │  │  └─ [디자인엔 데모 프리셋 버튼 2개(IMPORT_DEMO_FILES) — 실구현 제외] 실제로는 <input type="file" accept=".xlsx,.xls">(숨김) + label/버튼 트리거 + 드롭존 자체의 drag&drop(dragover/drop) 핸들러로 대체
│  │  └─ [phase=picked | uploading] 선택된 파일 표시 행 (배경 강조, radius md)
│  │     ├─ 파일명 (bold) + 파일 크기 (보조 텍스트)
│  │     └─ 우측: [picked] Button(ghost, sm, "제거") | [uploading] 텍스트 "업로드 중…" (primary색, bold)
│  ├─ 안내 텍스트 블록 (2줄, caption 크기, secondary 색)
│  │  ├─ "도서명 + 출판사 + 저자가 모두 같으면 동일 도서로 보고 소장본만 추가합니다"
│  │  └─ 거부 사유 4종 안내 (형식 오류/읽기 실패/필수 컬럼 없음/20MB 초과)
│  └─ 액션 영역 (우측 정렬)
│     └─ Button(primary, disabled=phase!=='picked', label: phase==='uploading' ? "업로드 중…" : "엑셀 파일 등록")
│
├─ [phase: success] 블록
│  ├─ Card — 결과 배너 (반복 패턴 A, error 배너와 쌍)
│  │  ├─ 아이콘 원 (44×44, radius lg, 배경 success-light, 체크 아이콘 svg, 색 success)
│  │  └─ 텍스트: 타이틀("{createdBooks}권 등록완료 (경고 {warnRows}건)", 18/700) + 서브("{파일명} · 시트 {N}개 · {committedAt} 처리", 13/secondary)
│  ├─ StatCard × 4 (반복 — 중복 후보 아님, 기존 컴포넌트 그대로 재사용) — grid auto-fit minmax(200px,1fr), gap 20
│  │  ├─ "처리 행" / totalRows / sub="시트 {N}개"
│  │  ├─ "등록 도서" / createdBooks / sub="신규 생성"
│  │  ├─ "등록 소장본" / createdBookItems / sub="전량 대출 가능 상태"(success 색)
│  │  └─ "정상 / 경고" / "{okRows} / {warnRows}" / sub="경고 행도 값을 정규화해 등록됨"
│  ├─ Card (title="경고 목록", noPadding, titleRight=Button(ghost, sm, 펼치기/접기 토글 — "{warnRows}건 펼치기" ↔ "접기"))
│  │  └─ [펼침 시] DataTable(경고 rows, 컬럼 5개: 시트/행/관리번호/도서명/내용)
│  └─ 액션 영역 (우측 정렬): Button(ghost, "다른 파일 등록") + Button(primary, "도서 검색으로 이동" → 기존 `/books/search`로 네비게이션)
│
└─ [phase: error] 블록
   ├─ Card — 결과 배너 (반복 패턴 A, success 배너와 쌍, tone만 danger)
   │  ├─ 아이콘 원 (44×44, radius lg, 배경 danger-light, X 아이콘 svg, 색 danger)
   │  └─ 텍스트: 타이틀("오류 {errorRows}건으로 등록되지 않았습니다", 18/700) + 서브("오류가 있으면 파일 전체가 등록되지 않습니다 (all-or-nothing)", 13/secondary)
   ├─ 안내 배너 (배경 danger-light, 텍스트 danger/bold, "엑셀 파일을 직접 고쳐서 다시 업로드해주세요. 화면에서 행을 직접 수정하는 기능은 없습니다.")
   ├─ Card (title="오류 목록", noPadding)
   │  └─ DataTable(오류 rows, 컬럼 6개: 시트/행/관리번호/도서명/필드/내용 — message 셀은 danger 색, 빈 값은 "—")
   └─ 액션 영역 (우측 정렬): Button(primary, "파일 다시 업로드" → reset)
```

**상태 전이 요약**: `idle → (파일 선택) → picked → (업로드 클릭) → uploading → (서버 응답) → success | error`. `error`에서 "파일 다시 업로드"는 `idle`로 리셋. `success`에서 "다른 파일 등록"도 `idle`로 리셋.

### 2) 내보내기 (`DataExportScreen` → 가칭 라우트 `/exports/excel`)

```
Page
├─ PageHeader (title="내보내기", description="저장된 데이터를 엑셀 파일로 바로 다운로드합니다 · 도서 / 소장본 / 대여 세 시트")
│
└─ 2컬럼 영역 (flex, wrap, gap 20 — flex-basis 520px(좌) / 360px(우), 좁아지면 자동 줄바꿈)
   ├─ Card (title="포함할 시트", flex 2)
   │  └─ CheckRow × 3 (반복 — 중복 후보, 시트별 체크박스 행)
   │     ├─ 도서 (checked 기본 true) — 컬럼 미리보기 텍스트: 실제 API 컬럼으로 표시(아래 데이터 shape 참고, 디자인 목업 컬럼과 다름)
   │     ├─ 소장본 (checked 기본 true)
   │     └─ 대여 (checked 기본 true)
   │     각 행: 선택 시 배경 primary-light + border, 미선택 시 배경 surface + border 기본색. radius md, padding 14/16.
   └─ Card (title="내보내기 옵션", flex 1)
      ├─ "대여 기간" 라벨(13/600) + Input(type=date) × 2 + "~" 구분자 + 보조텍스트("대여 시트에만 적용됩니다", 12/secondary)
      ├─ Toggle × 2 (반복 — 중복 후보)
      │  ├─ "분실·폐기 소장본 포함" (기본 on=true → API `includeInactiveItems` 기본값 true와 일치)
      │  └─ "미반납 건만 내보내기" (기본 on=false → API `unreturnedOnly` 기본값 false와 일치)
      ├─ 파일명 미리보기 박스 (배경 bg, radius sm, 라벨 "파일명" + 값) — **미확정, 아래 참고**
      └─ Button(primary, fullWidth, disabled=선택된 시트 0개, "엑셀 내보내기")
```

**폼 상태 요약**: 시트 선택(Set, 최소 0~최대 3) × 날짜 범위(선택) × 토글 2개(boolean) → "엑셀 내보내기" 클릭 시 `POST /exports/excel` 호출 → 성공 시 Blob 다운로드 트리거(브라우저 저장) + 완료 토스트, 실패 시(`NO_SHEET_SELECTED`/`INVALID_DATE_RANGE`) 에러 토스트 또는 필드 에러.

## 디자인 토큰

원본은 `var(--color-*)` CSS 변수와 인라인 px 값을 쓴다. 정확한 Tailwind `@theme` 토큰 매핑은 **component-architect가 기존 `globals.css`를 확인해 확정**할 것 — 여기서는 의도와 근사 대응만 기록한다.

| 범주 | 원본 값 | 의도 / 근사 매핑 | 비고 |
|------|---------|------------------|------|
| 색상 · 주요 | `var(--color-primary)`, `var(--color-primary-light)` | primary / primary-light | 버튼, 선택 강조, 업로드중 텍스트 |
| 색상 · 성공 | `var(--color-success)`, `var(--color-success-light)` | success / success-light | 등록 성공 배너·아이콘, 정상 소장본 sub |
| 색상 · 위험 | `var(--color-danger)`, `var(--color-danger-light)` | danger / danger-light | 오류 배너·아이콘, 오류 메시지 셀 |
| 색상 · 경고(주의) | `#8A5A00` / `#FFF4E0` (Pill의 `warn` 톤, 하드코딩 hex) | warning / warning-light 추정 | **토큰 미사용 하드코딩** — 코드베이스 `@theme`에 warning 계열 있으면 그걸 쓸 것 (StatCard에 이미 `warning` tone 있음) |
| 색상 · 표면/배경 | `var(--color-surface)`, `var(--color-bg)` | surface / canvas(bg) | Card 표면, 드롭존 배경 |
| 색상 · 텍스트 | `var(--color-text-primary)`, `var(--color-text-secondary)`, `var(--color-text-placeholder)` | fg / fg-muted / fg-placeholder(추정) | |
| 색상 · 테두리 | `var(--color-border)` | border | 드롭존 점선, CheckRow 테두리 |
| 색상 · copy(소장본 계열) | `var(--color-copy-light)` | copy-light | StatCard "등록 소장본" 아이콘 배경(디자인 목업, 실제 StatCard는 `tone` enum 사용 — 아래 컴포넌트 인벤토리 참고) |
| 타이포 · 헤딩 | 28/700, letterSpacing -0.03em | PageHeader 기존 `text-3xl font-bold tracking-tight` 그대로 | 기존 컴포넌트가 이미 이 스타일 보유 |
| 타이포 · 결과 타이틀 | 18/700, letterSpacing -0.02em | heading-sm 급 | 성공/오류 배너 타이틀 |
| 타이포 · 본문 강조 | 14~15/600 | body-strong 급 | 파일명, CheckRow 라벨 |
| 타이포 · 보조 | 12~13/400 | caption / body-muted | sub 텍스트, 안내문 |
| 간격 | 4/6/8/10/14/16/20/24/44px 다수 | xs~2xl 스케일로 정리 필요 | 44px는 드롭존 상하 패딩 전용값(1회성 가능) |
| 반경 | 6(Pill), 8(안내배너·데모버튼), 10(파일표시행·CheckRow), 12(Card·아이콘원), 9999(Toggle·Pill 알약형) | sm/md/lg/full | |
| 그림자 | `var(--shadow-sm)` (Toggle 손잡이만) | shadow-sm | Card 자체는 "no drop shadow" 원칙(기존 Card 주석과 일치) |
| 브레이크포인트 | 명시 없음(뷰포트 1440×900 고정 프로토타입) | — | 내보내기 화면의 `flexWrap`만 암묵적 반응형 단서 |

| `Toast` | 완료/실패 알림 | 화면당 1 (사용 조건 불명확) | 아니오 | **기존 재사용** (`ui/toast.tsx`) | 원본은 로컬 `msg` 문자열 state로 단순 노출하지만 실제 컴포넌트는 `open`/`tone`/`duration` controlled API — 배선 재설계 필요 |
| **`Pill`** | 톤별 알약형 라벨(ok/warn/error/info) | 정의만 있고 **이 두 화면 렌더 트리 안에서는 실사용 흔적 없음** | — | **신규 후보(보류)** | 아래 "미확정" 참고 — Badge와 기능 중복 가능성 있어 도입 전 확인 필요 |

| **`CheckRow`** | 체크박스 + 콘텐츠 행(카드형) | 3 (내보내기 화면, 시트 선택) | **예** | **신규 필요** | 코드베이스에 체크박스 프리미티브 자체가 없음(순수 신규). 선택 시 배경 강조 variant 필요 |
| **결과 배너(성공/오류 공통 레이아웃)** | 아이콘원 + 타이틀 + 서브텍스트, Card 안에 배치 | 2 (성공 1회, 오류 1회 — **모양 동일, tone만 다름**) | **예** | **신규 필요(합성 컴포넌트)** | success/danger 두 곳에서 구조가 완전히 동일(44px 아이콘원 + 텍스트 2줄) — 단일 컴포넌트 + tone variant로 통합 강력 추천. `library/`에 두는 게 적절(엑셀 등록 도메인 종속) |
| **파일 드롭존 + 선택 파일 표시** | 파일 피커 UI(idle) / 선택된 파일 카드(picked·uploading) | 화면당 1(상태별 2뷰) | 아니오(반복은 없으나 로직 복잡) | **신규 필요** | 실제 `<input type="file">` + drag&drop 이벤트 필요. 디자인의 `IMPORT_DEMO_FILES` 프리셋 버튼은 **실구현 제외** |
| `Badge` | — | 이번 두 화면엔 미사용 | — | 기존 컴포넌트 있음(참고용) | Pill 도입 여부 판단 시 비교 대상 |

**정리**: 신규로 반드시 만들어야 하는 것은 `Toggle`, `CheckRow`(체크박스 프리미티브), 파일 피커/드롭존, 결과 배너(success/error 공용) 4가지다. `Pill`은 이 두 화면에 실제로 등장하지 않으므로 이번 작업 범위에서는 만들지 않는 것을 권장하되, 판단은 component-architect에게 넘긴다.

| 업로드 중 | 버튼 라벨 "업로드 중…"으로 변경, 파일 표시 행 우측 텍스트도 "업로드 중…"(재확인 필요 — 버튼과 텍스트 이중 표시가 의도인지 **미확정**) |

| 응답 400/413 | **디자인엔 이 경로 자체가 없음** — `ApiError`로 던져지는 요청 자체 실패. 화면 처리 방식(토스트? 인라인 에러?) **미확정 — 확인 필요** |

## 반응형 규칙

디자인 원본은 1440×900 고정 뷰포트 프로토타입이며 **명시적 브레이크포인트가 없다.**

## 데이터/콘텐츠 형태

**아래는 디자인 목업이 아니라 `api-notes.md`(실제 백엔드 계약) 기준이다.** 디자인 렌더 코드의 `IMPORT_SUCCESS`/`IMPORT_ERROR`/`EXPORT_SHEETS` 목업 값은 화면 레이아웃 참고용으로만 쓰고, 아래 타입/값으로 대체한다.

### 엑셀 일괄 등록 — `POST /imports/excel`

- 요청: `multipart/form-data`, 필드명 `file` (단일 `MultipartFile`, `.xlsx`/`.xls`, 최대 20MB)
- 응답은 **discriminator 필드 없이 HTTP 상태로만 구분**된다(JSON 바디에 type 표시 없음):

```ts
// 201 Created
type ImportCommitted = {
  committedAt: string; // LocalDateTime, "T" 포함 ISO 형태
  sheets: string[];
  totalRows: number;
  createdBooks: number;
  createdBookItems: number;
  okRows: number;
  warnRows: number;
  warnings: RowResult[];
};

// 409 Conflict
type ImportRejected = {
  errorRows: number;
  errors: RowResult[];
};

type RowResult = {
  sheet: string;
  rowNumber: number;
  managementNumber: string | null;
  title: string | null;
  code: string | null;   // ExcelImportRowCode — 아래 참고
  message: string | null; // 화면엔 이 메시지를 그대로 렌더. code로 분기 로직 만들지 말 것
  errorField: string | null;
};
```

- `ExcelImportRowCode`(실제 enum, **디자인 목업 코드값과 다름**): `MANAGEMENT_NUMBER_REQUIRED`, `TITLE_REQUIRED`, `MANAGEMENT_NUMBER_INVALID_FORMAT`, `DUPLICATE_MANAGEMENT_NUMBER_IN_FILE`, `DUPLICATE_MANAGEMENT_NUMBER_IN_DB` (이상 오류), `MANAGEMENT_NUMBER_NORMALIZED`(경고), `EXISTING_BOOK_ITEM_ADDED`(경고), `AUTHOR_BLANK`(경고), `PUBLISHER_BLANK`(경고). 디자인 목업의 `AUTHOR_MISSING_DEFAULTED`/`DUPLICATE_BOOK_MERGED`는 실제 enum에 없음 — 각각 `AUTHOR_BLANK`/`EXISTING_BOOK_ITEM_ADDED`에 대응하는 것으로 추정(**미확정**, message 텍스트를 그대로 쓰면 큰 문제 없음).
- 400/413 (요청 자체 실패, `ProblemDetail` 형태): `INVALID_FILE_TYPE`(400), `UNREADABLE_FILE`(400), `REQUIRED_COLUMN_NOT_FOUND`(400), `FILE_TOO_LARGE`(413)
- **전용 fetch 함수 필요**(신규): multipart 바디 전송 + 201/409 바디를 유니온 타입(`ImportCommitted | ImportRejected`, 응답 status로 분기)으로 그대로 반환, 400/413만 기존 `ApiError` 경로. `apiFetch`는 이 엔드포인트에 쓸 수 없음(JSON 전용 + 비-ProblemDetail 바디 유실).
- 헤더 매핑(`ExcelColumnMapper`): 엑셀 헤더 `도서번호`→관리번호(필수), `도서명`→도서명(필수), `출판사명`→출판사(선택), `저자명`→저자(선택). 순서 무관, 이름 완전 일치.

### 내보내기 — `POST /exports/excel`

```ts
type ExportRequest = {
  sheets: ("BOOKS" | "BOOK_ITEMS" | "LOANS")[];
  loanDateFrom?: string; // LocalDate
  loanDateTo?: string;   // LocalDate
  includeInactiveItems?: boolean; // 기본 true
  unreturnedOnly?: boolean;       // 기본 false
};
// 응답: 성공 시 Blob(xlsx) + Content-Disposition의 filename
// 실패 시(400, ProblemDetail): NO_SHEET_SELECTED | INVALID_DATE_RANGE
```

- **전용 fetch 함수 필요**(신규): 성공 시 `{ blob: Blob; filename: string }` 반환(파일명은 `Content-Disposition` 헤더 파싱, 클라이언트에서 조합 금지), 실패 시 `ProblemDetail` 파싱해 `ApiError` throw.
- **시트별 실제 컬럼(디자인 목업과 다름 — 화면 미리보기 텍스트도 이 값으로 교체할 것)**:
  - `BOOKS`(도서): 도서ID, 도서명, 저자, 출판사, ISBN, 등록일시 — *디자인엔 없던 "도서ID" 추가, 디자인에 있던 "소장본 수" 삭제*
  - `BOOK_ITEMS`(소장본): 소장본ID, 도서ID, 관리번호, 상태, 등록일시 — *디자인에 있던 "도서명"/"최근 대출일" 삭제(조인 없음)*
  - `LOANS`(대여): 대여ID, 소장본ID, 관리번호, 도서명, 대출자, 부서, 이메일, 대출일, 반납예정일, 반납일, 상태 — *디자인엔 없던 "대여ID"/"소장본ID"/"이메일" 추가*
- 시트별 행 수(디자인의 4399/4838/2841)는 **목업 고정값**이다. 실제 카운트 조회 API가 없으므로 화면에 행 수를 표시하지 않는다(CheckRow 설명에서 원본의 `rows` 값 제거).

## 미확정 항목 (확인 필요)

1. **`Pill` 컴포넌트 실사용 여부** — 정의는 공용 UI 섹션에 있으나 `ExcelImportScreen`/`DataExportScreen` 렌더 트리 안에서는 호출되는 곳이 없다. 이번 두 화면에 실제로 필요한지, 아니면 트리밍 과정에서 우연히 남은 정의인지 리더 확인 필요. 필요하다면 기존 `Badge`와 기능이 겹치는지부터 비교할 것.
2. **`Toast` 트리거 시점** — 원본 코드에 `toast` state와 렌더는 있으나 `setToast(...)` 호출부가 실제로는 없다(둘 다 정의만 있고 미사용 dead state에 가까움). 엑셀 등록/내보내기 각각 어떤 이벤트에서 Toast를 띄울지 확정 필요(예: 업로드 실패 400/413 시? 다운로드 완료 시만?).
3. **StatCard `tone`/`subTone` 매핑** — 실제 컴포넌트는 색상 enum만 받는데 디자인은 임의 hex/var를 씀. 4개 카드 각각 어떤 tone을 쓸지(예: "등록 소장본"을 `copy`로 할지 `success`로 할지) architect 판단 필요.
4. **드래그오버 시각 피드백** — 디자인엔 정적 드롭존 스타일만 있고 dragover/dragleave 시 강조 스타일 명시 없음.
5. **400/413(요청 자체 실패) 시 화면 처리** — 디자인엔 이 실패 경로 자체가 없음(idle/picked/uploading/success/error 4단계에 대응 안 됨). Toast로 처리할지, uploading에서 idle/picked로 되돌리며 인라인 에러를 보여줄지 결정 필요.
6. **내보내기 파일명 미리보기 UI 존치 여부** — 서버가 파일명을 최종 결정하므로(`Content-Disposition`) 다운로드 전 미리보기가 부정확할 수 있음. 그대로 두되 "예상 파일명"으로 문구를 바꿀지, 아예 제거하고 다운로드 완료 토스트에만 실제 파일명을 노출할지 확인 필요.
7. **날짜 Input 기본값 정책** — 디자인은 `2026-01-01~2026-04-01` 하드코딩. 실제로는 빈 값(전체 기간)이 기본이어야 하는지, 최근 N개월 등 정책이 있는지 미확정.
8. **`INVALID_DATE_RANGE` 프론트 사전 검증 여부** — 서버가 400으로 걸러주지만, UX상 버튼 disabled 또는 인라인 에러로 미리 막을지 결정 필요.
9. **엑셀 등록 헤더 매핑 표를 화면에 노출할지** — 안내 텍스트에 "필수 컬럼" 언급은 있으나 정확한 헤더명(도서번호/도서명/출판사명/저자명)까지 화면에 보여줄지는 디자인에 없음. UX 결정 사항으로 남김.

## component-architect 전달 사항 (반복 UI 패턴 강조)

파일 상단 CLAUDE.md 규약상 팀 간 SendMessage 도구가 준비되지 않아, 아래 내용을 이 문서에 명시하는 것으로 갈음한다.

1. **`Toggle`** — 내보내기 화면에 2회 반복. 코드베이스에 스위치류 프리미티브가 전혀 없음. `ui/`에 신규 프리미티브로 추가 권장(`on`/`onChange`/`label`, 필요시 `disabled`).
2. **`CheckRow`** — 내보내기 화면에 3회 반복(시트 선택). 코드베이스에 체크박스 프리미티브 자체가 없음(순수 신규 필요). 선택 시 배경 강조되는 카드형 variant가 필요.
3. **성공/오류 결과 카드 레이아웃** — 엑셀 등록 화면의 success/error 각 1회씩, 총 2곳에서 "44px 아이콘원 + 타이틀 + 서브텍스트" 구조가 tone만 다르고 완전히 동일하다. 단일 컴포넌트(예: `ImportResultBanner`, `library/` 계층)로 통합하고 `tone`(success/danger) variant로 색상만 분기할 것을 강력 권장 — 지금 통합하지 않으면 향후 유사 결과 화면이 늘 때마다 같은 마크업이 반복될 가능성이 높다.
4. **`StatCard`/`Card`/`Button`/`Input`/`DataTable`/`Toast`는 기존 컴포넌트 그대로 재사용** 가능 — 신규 variant 추가 없이 prop만 채우면 된다(단, StatCard tone 매핑은 미확정 항목 #3 참고).
5. **`Pill`은 이번 두 화면에 실사용처가 없으므로 신규 추가 보류 권장** — 미확정 항목 #1 참고, 리더 확인 후 필요성 재검토.

## 리더 결정 (미확정 항목 #1~9 해소)

사용자에게 재확인이 필요한 API/디자인 충돌은 아니라고 판단해 리더가 직접 결정한다. component-architect/frontend-implementer는 아래를 그대로 따를 것.

1. **`Pill`** — 만들지 않는다. 이번 두 화면에 실사용처 없음.
2. **`Toast` 트리거** — 실제 이벤트에 연결한다. 엑셀 등록: 400/413(요청 자체 실패) 시 `tone="danger"`로 `error.detail` 노출. 내보내기: 다운로드 성공 시 `tone="success"`로 "{파일명} 파일을 다운로드했습니다.", 400 실패 시 `tone="danger"`로 `error.detail`.
3. **StatCard tone 매핑** — "처리 행"=`primary`, "등록 도서"=`primary`, "등록 소장본"=`copy`(subTone `success`), "정상 / 경고"=`warning`(경고가 0건이어도 항상 이 카드 자체는 warning 계열 아이콘 배경 — 디자인의 `#FFF4E0` 의도 계승).
4. **드래그오버 시각 피드백** — 추가한다. dragover 시 드롭존 테두리를 `border-primary` + 배경을 `primary-light`로 살짝 강조, drop/dragleave 시 원복. 표준 드래그앤드롭 UX이므로 디자인에 없어도 구현한다.
5. **400/413 처리** — 토스트(danger)로 `error.detail` 노출, phase는 `picked`로 되돌린다(파일 재선택 없이 재시도 가능하게). `uploading` 스피너만 해제.
6. **내보내기 파일명 미리보기** — 유지하되 라벨을 "예상 파일명"으로 바꾸고, 실제 파일명은 다운로드 완료 토스트에서 `Content-Disposition` 기준 값을 보여준다.
7. **날짜 Input 기본값** — 디자인의 하드코딩 날짜 대신 **둘 다 빈 값(전체 기간)**을 기본으로 한다. API가 optional이므로 빈 값이면 `loanDateFrom`/`loanDateTo`를 요청 바디에서 생략한다.
8. **`INVALID_DATE_RANGE` 프론트 검증** — 프론트에서 `from > to`면 "엑셀 내보내기" 버튼을 비활성화하고 인라인 에러 문구를 보여준다(서버 400 요청 자체를 막아 UX를 개선). 서버가 그래도 400을 반환하면 Toast(danger)로 폴백.
9. **헤더 매핑 안내 노출** — 노출한다. 안내 텍스트에 "필수: 도서번호, 도서명 · 선택: 출판사명, 저자명" 한 줄을 추가한다(정확한 헤더명을 몰라 업로드가 반복 거부되는 상황 방지).
