# 디자인 스펙: 연체 목록 (`OverdueScreen`)

## 개요

부서명으로 좁혀 볼 수 있는 연체 대출 조회 전용 화면이다(등록·수정·액션 없음). 라우트는 이미 `src/app/overdue/page.tsx`에 `PagePlaceholder`로 스캐폴딩되어 있고 `LIBRARY_NAV_ITEMS`(`href: "/overdue"`)에도 등록되어 있어, 이번 작업은 그 자리를 실제 화면으로 교체하는 것이다.

**디자인 vs 백엔드 간극과 해결 방향(확정, 지어낸 것 아님):**
- 디자인 원문(`OverdueScreen` JSX)은 `SearchInput` 1개로 도서명·대출자·부서·관리번호를 OR 검색하는 것을 전제로 하고, `DataTable`의 `pageSize=20` 클라이언트 배열 페이지네이션을 쓴다. 이는 디자이너가 만든 로컬 목업 데이터(`OVERDUE = LOANS.filter(status==='overdue')`)에서 나온 전제일 뿐, 실제 API 계약이 아니다.
- 실제 `GET /loans/overdue`는 **`department` 부분 일치 파라미터 하나만** 지원하고, 서버 페이지네이션(`page`/`pageSize`, 응답 `pagination`)이다. 도서명·대출자·관리번호로는 필터링할 수 없다.
- 따라서 이 스펙은 `#15`(대출 내역 조회)가 같은 종류의 간극을 풀었던 원칙 — **서버가 실제로 지원하는 필터만 노출하고, 페이지네이션은 서버 계약(`serverPagination`)에 맞춘다** — 을 그대로 따른다. 통합 검색창·클라이언트 필터·"도서명, 대출자, 부서, 관리번호 검색" 플레이스홀더는 채택하지 않는다.
- `overdueDays`는 서버가 조회 시점 기준으로 계산해 내려주는 값이다. 프론트는 이 값을 그대로 표시만 하고 날짜 차이로 재계산하지 않는다(`LoanListCard`/`ReturnListCard`가 `overdue`를 재계산하지 않는 것과 동일 원칙).
- 시각적 톤(필터 바 + 목록 카드, 카드 간 여백, 배지/강조 텍스트 스타일)은 디자인을 보존한다 — 바뀌는 것은 필터 UI 구성과 페이지네이션 전략뿐이다.

## 디자인 토큰

내보낸 JSX는 인라인 스타일(`style={{...}}`)을 쓰지만, 이미 코드베이스 프리미티브(`Card`, `PageHeader`, `Badge`, `DataTable`)가 그 값들을 `@theme` 토큰으로 흡수해 두었다. 이 화면은 새 토큰이 필요 없고 기존 값을 그대로 재사용한다.

| 범주 | 값(토큰) | 근거 |
|------|---------|------|
| 페이지 패딩 | `layout.tsx`의 `<main>` 소유 (디자인 원문 `padding:'32px 40px'`는 이미 흡수됨) | 확인됨 — README "페이지 좌우/상하 여백은 `<main>`이 소유" |
| 카드 간 간격 | 필터 Card `mb-5`(=20px, `LoanHistoryCard` 전례) | 추론 — 디자인 원문 `marginBottom:16`과 소폭 차이나나, 기존 화면(`LoanHistoryCard`)이 이미 `mb-5`로 정착시킨 값을 따름(일관성 우선) |

| 브레이크포인트 | `sm`(Tailwind 기본값) | 추론 — `LoanHistoryCard`가 이미 쓰는 분기점 재사용 |

**총평 (component-architect에게):** 이 화면은 신규 UI 프리미티브가 필요 없다. 유일한 진짜 신규 산출물은 (1) `OVERDUE_LOAN_COLUMNS` 컬럼 정의, (2) `lib/api/loans.ts`에 추가할 `OverdueLoanSummary`/`OverdueLoanSearchResult`/`searchOverdueLoans()`, (3) 이 둘을 조립하는 도메인 컴포넌트(가칭 `OverdueListCard`, `library/` 계층) 정도다. 구조적으로 `LoanHistoryCard`를 거의 그대로 축소 복제하는 형태이므로, 필터 바 골격·목록 카드 헤더 골격·디바운스+서버 페이지네이션 배선 로직을 `LoanHistoryCard`에서 공통 추출할 가치가 있는지(필터 필드 개수만 다름 — 1개 vs 3개+select) 판단이 필요하다. 다만 필터 필드 구성이 이질적이라(연체는 단일 텍스트 필드, 이력은 텍스트 3개+select) 억지 일반화보다는 `library/loan-table.ts`처럼 "진짜 겹치는 조각"(컬럼 폭 관례, 디바운스 훅)만 공유하고 카드 자체는 별도로 두는 쪽이 기존 원칙(`ReturnListCard`/`LoanHistoryCard` 분리 사유와 동일선상)에 부합할 가능성이 높다 — 단정하지 않고 판단을 넘긴다.

**아키텍트 회신(확정):** 넘겨받은 판단은 후자로 확정했다 — **카드는 분리(`OverdueListCard` 신규), 공유는 "진짜 겹치는 조각"만.** 필터 카드 골격·목록 카드 헤더 골격은 공유하지 않는다(둘 다 `Card` prop 조합 + 클래스 문자열 2줄이라 래퍼를 만들면 이름만 늘고 이득이 없다). 대신 이번 스캔에서 **4벌로 복제된 "에러 + 다시 시도" 블록**(`BookListCard`/`LoanListCard`/`ReturnListCard`/`LoanHistoryCard`, 마크업·문구·동작이 바이트 단위로 동일)을 발견해 `ui/list-error-state.tsx`로 승격한다 — 이것이 이 화면 작업에서 뽑을 진짜 중복이다. 근거와 전체 결정은 `_workspace/02_component-plan.md` 참조.

## 상태 & 상호작용

| 요소 | 상태/동작 |
|------|----------|
| 부서 `Input` | 타이핑 → `useDebouncedValue`(기본 250ms) 후 서버 재조회. 값 변경 시 페이지 1로 리셋(`LoanHistoryCard`의 `filterKey` 비교 패턴 재사용) |
| 초기화 `Button` | 클릭 시 부서 입력값 빈 문자열로. `disabled={!hasFilter}`(부서 값이 비어있으면 비활성) — `LoanHistoryCard`/`ReturnListCard` 전례 |
| 목록 `Card` 헤더 배지 | `{pagination.totalElements.toLocaleString()}건` — **클라이언트 배열 길이(`rows.length`)가 아니라 서버 응답 `pagination.totalElements`를 표시한다.** 디자인 원문의 `rows.length`는 클라이언트 필터 전제였으므로 채택하지 않음 |
| `DataTable` | `loading` prop으로 로딩 표시(기존 표는 스켈레톤 없이 dimmed 처리 — `LoanHistoryCard` 패턴 재사용). 에러 시 신규 `ListErrorState`(에러 문구 + "다시 시도")를 표 대신 렌더 — 기존 4개 카드가 인라인으로 복제하던 블록을 프리미티브로 승격해 그것을 쓴다(결정 4) |
| 경과일수 셀 | **확정 — ① plain 강조 텍스트.** `renderCell`에서 `col.key === "overdueDays"`일 때 `<span className="text-base font-semibold text-danger">{overdueDays}일 경과</span>`. `Badge`는 쓰지 않는다(결정 1 근거 참조) |
| `serverPagination` | `Pagination`(`ui/pagination.tsx`)이 `DataTable` 내부에서 자동 렌더 — 별도 페이지네이션 UI를 표 아래에 손으로 붙이지 않는다(README 원칙) |
| 빈 상태 | `emptyText="연체 중인 도서가 없습니다."` (확인됨 — 디자인 원문 그대로, `department` 필터가 걸려있든 없든 동일 문구) |
| 행 클릭 | 미확정 — 디자인 원문에 `onRowClick` 없음. 상세 화면/모달 없음으로 간주(클릭 불가 행) |
| hover/focus/active | `DataTable` 기본 동작(`hover:bg-surface-muted`, 포커스는 클릭 가능한 행에만 적용되며 이 화면은 비클릭 행이라 해당 없음) |

## 반응형 규칙

- **base(모바일)**: 필터 바 `flex-col`(Input과 Button 세로 스택), 표는 `overflow-x-auto`(DataTable 기본 동작)로 가로 스크롤
- **sm 이상**: 필터 바 `flex-row items-center`, Input이 `flex-1`로 늘어나고 Button은 `shrink-0`
- 카드/헤더/표 자체의 반응형 분기는 디자인 원문에 명시 없음 — `LoanHistoryCard`가 이미 정착시킨 `sm` 분기 재사용(추론)

## 데이터/콘텐츠 형태

```ts
// src/lib/api/loans.ts에 추가 (기존 파일 확장 — 신규 파일 아님)

// ⚠️ interface 아닌 type 별칭 (DataTable<T extends Record<string, unknown>> 제약, books.ts/loans.ts 관례)
export type OverdueLoanSummary = {
  loanId: number;
  managementNumber: string;
  bookTitle: string;
  borrowerName: string;
  department: string;
  /** LocalDate "YYYY-MM-DD" */
  loanDate: string;
  /** LocalDate "YYYY-MM-DD" */
  dueDate: string;
  /** 서버가 조회 시점 기준으로 계산한 값. 프론트에서 날짜로 재계산하지 않는다 */
  overdueDays: number;
};

export type OverdueLoanSearchResult = {
  loans: OverdueLoanSummary[];
  pagination: PaginationMeta; // client.ts의 공용 타입 재사용 — 도메인 파일에 복제 금지
};

export type SearchOverdueLoansParams = {
  /** 부서명 부분 일치. 빈 문자열은 buildUrl이 자동 누락 */
  department?: string;
  /** 1-based */
  page?: number;
  /** 기본 10, 최대 100 */
  pageSize?: number;
};

// searchOverdueLoans(params, signal): Promise<OverdueLoanSearchResult>  — GET /loans/overdue
```

**정렬 관련 참고(미확정 아님, 사실):** 서버 정렬은 `dueDate` ASC, `id` ASC로 고정이며 요청 파라미터로 바꿀 수 없다. 프론트는 정렬 UI(컬럼 헤더 클릭 정렬 등)를 만들지 않는다 — 디자인 원문에도 그런 UI가 없다.

## 확정 결정 (component-architect, 2026-08-13)

초안의 미확정 5건은 아래로 확정한다. 구현자는 이 절을 계약으로 삼는다(재논의 불필요).

1. **경과일수 셀 표현 → plain 강조 텍스트(디자인 원문 유지).** `<span className="text-base font-semibold text-danger">{overdueDays}일 경과</span>`.
   근거: (a) 이 코드베이스에서 pill(`Badge`)은 **상태 어휘**를 담는 형태다 — `StatusBadge`(대출중/연체/반납완료)가 그 자리를 이미 점유했고, 같은 표 계열에서 수치(경과일)를 같은 형태로 그리면 "상태 배지"와 "수치"가 시각적으로 뭉개진다. (b) 디자인 원문도 pill이 아니라 텍스트 강조다. (c) 재사용 원칙은 "같은 의미의 UI를 다시 만들지 말 것"이지 "모든 강조를 `Badge`로 통일"이 아니다 — 여기서 `Badge`를 쓰는 건 재사용이 아니라 의미 오용이다.
   `text-sm`이 아니라 **`text-base`**다(`--text-base: 13px`, `--text-sm: 12px`). 셀 1곳 전용이라 별도 컴포넌트로 추출하지 않는다(YAGNI).
2. **총 건수 배지 톤 → `variant="soft" tone="danger"`.**
   근거: 디자인 원문의 `color=var(--color-danger)` + `bg=var(--color-danger-light)`는 `Badge`의 `soft`×`danger` compoundVariant와 **값이 정확히 일치**한다 — 커스텀 색 요구가 아니라 기존 tone 축의 정상 사용이므로 디자인을 굽힐 이유가 없다. `LoanHistoryCard`의 `neutral`과 갈리는 것이 아니라, 화면 성격(연체=위험)에 맞는 tone을 고른 것이다. 톤 선택지가 이미 컴포넌트 안에 있는데 화면마다 통일하라고 강제하면 variant 축이 죽는다.
3. **PageHeader description → "기준일" 문구 삭제.** 최종 문구: `"반납 예정일 익일부터 연체로 집계"`.
   근거: 서버 응답에 "조회 기준일" 필드가 없다. 프론트에서 `new Date()`로 찍으면 (a) 서버가 `overdueDays`를 계산한 기준일과 클라이언트 시계·타임존이 갈릴 때 **화면이 스스로 거짓말**을 하고("기준일 8/13"이라 적힌 옆에 다른 기준으로 계산된 숫자), (b) 이 페이지는 서버 컴포넌트라 렌더 시점 날짜가 박혀 hydration/캐시 경계에서 낡은 날짜가 남는다. 문구를 빼면 두 문제가 동시에 사라지고 정보 손실은 없다 — 실제 기준일 정보는 각 행의 `overdueDays`가 이미 담고 있다. 서버가 응답에 기준일을 내려주면 그때 되살린다.
4. **에러 상태 UI → 기존 패턴 채택 + 프리미티브로 승격.** 이 화면도 "에러 문구 + 다시 시도" 블록을 쓴다. 다만 이 블록은 이미 `BookListCard`/`LoanListCard`/`ReturnListCard`/`LoanHistoryCard` 4곳에 **바이트 단위로 동일하게 복제**돼 있다 → `ui/list-error-state.tsx`(`ListErrorState`)로 추출하고 4곳을 교체한 뒤, 이 화면은 5번째 사용처로 그것을 쓴다. (디자인 원문에 에러 상태가 없는 것은 정적 목업이기 때문이며, 실제 API를 붙이는 이상 필수다.)
5. **필터 Card `role="search"` → 부착.** `<Card padding="sm" role="search" aria-label="연체 목록 부서 검색">`. `LoanHistoryCard` 전례를 따른다 — 검색 랜드마크가 화면마다 있거나 없으면 스크린리더 사용자의 탐색 경험이 갈린다.
