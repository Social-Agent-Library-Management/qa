# 01. 디자인 스펙 — 반납 처리 (`ReturnProcessingScreen`)

소스: Claude Design `307f4357-…` `ui_kits/library/index.html`, `ReturnProcessingScreen` 컴포넌트.
원문 발췌는 `00_input/design-note.md` 참조.

## 레이아웃 트리
- `PageHeader`(title="반납 처리", sub="대출 중인 소장본만 반납 처리할 수 있습니다")
- `Card`(검색) → 통합 검색 입력 1개(관리번호/도서명/대출자)
- `Card`(title="반납 처리 대상", noPadding) → `DataTable`(columns: 관리번호·도서명·대출자·부서(secondary)·반납예정일(secondary)·상태·액션(라벨 없음), pageSize=20)
  - 상태 컬럼: `Badge status={done ? 'returned' : v}` — 원본은 로컬 `done` Set으로 낙관적 표시
  - 액션 컬럼: 미처리 시 `Button variant=success size=sm` "반납 처리", 처리완료 시 "처리완료" 텍스트
- `Toast` — 반납 처리 성공 시 `"${title}" 반납 처리되었습니다.`

## 상태/상호작용
- `search` — 검색어(관리번호/도서명/대출자 부분 일치, OR)
- `done: Set<copyNo>` — 원본은 클라이언트 로컬 상태로 낙관적 처리(재조회 없음)
- 대상 행: `status !== 'returned'`인 대출만(연체 포함)

## 백엔드 대조 (실제 구현 시 조정 필요 항목)
- `GET /loans` 검색은 `bookTitle`/`borrowerName`/`department`만 지원 — **관리번호 필터 없음**
  (`LoanRepository.search`, `LoanController.search`). 원본의 단일 검색창(관리번호 포함)은
  서버 필터로 그대로 옮길 수 없다 → 아키텍처 결정 필요(02 참조)
- `POST /loans/{loanId}/return` — 바디 없이 호출 가능(`returnedAt` optional, 기본 오늘).
  에러: `LOAN_NOT_FOUND`(404), `LOAN_NOT_ON_LOAN`(409, 이미 반납됨 — 경합 가능)
- 원본의 로컬 `done` 낙관적 상태는 이 코드베이스 컨벤션(서버 확정 상태만 신뢰,
  `LoanListCard`/`BookListCard` 참고)과 어긋난다 → 반납 성공 시 재조회로 대체(02 참조)
