## 2. KPI StatCard ×4

원본은 `iconBg`에 CSS 변수 문자열을 직접 넘겼다. 코드베이스의 `StatCard`는 이를 `tone` 축으로
치환해 두었으므로 매핑해 쓴다.

| 라벨 | value | sub | tone | subTone |
|------|-------|-----|------|---------|
| 전체 도서 | `bookCount` | "등록된 서지 정보" | `primary` | `muted` |
| 전체 소장본 | `bookItemCount` | `대출 가능 {availableBookItemCount}권` | `copy` | `success` |
| 현재 대출 | `activeLoanCount` | "활성 대출 건수" | `success` | `muted` |
| 연체 항목 | `overdueLoanCount` | "즉시 확인 필요" | `danger` | `danger` |

원본은 값을 목업 배열 길이(`BOOKS.length` 등)에서 계산했다. 실제로는 전부 서버 집계값이다.

## 3. 최근 대출 활동

원본 컬럼: `title 30% / borrower 12% / dept 14%(secondary) / date 14%(secondary,nowrap) / status 10%`
→ 폭 합계 80%. **목업 오차다**(`LOAN_HISTORY_COLUMNS`의 94%와 같은 성격) → 비율 유지 후 100%로 정규화:
`bookTitle 37 / borrowerName 15 / department 18 / loanDate 18 / status 12`.

**라벨 이탈 1건:** 원본은 `date` 컬럼 라벨이 "대출일"이지만 코드베이스의 다른 두 대출 표는
같은 필드를 "대여일"로 부른다(`loan-table.ts`가 강제하는 규칙: 같은 키의 label은 표마다 동일).
서버 스키마도 `loanDate`/"대여일"이다 → **"대여일"을 쓴다.**

- 행 수: **10건**, 페이지네이션 없음 (사용자 지시 — `serverPagination` 미사용).
- `titleRight`의 "전체 보기" 링크: **구현 제외** (사용자 지시).
- 상태 배지: `status` 셀 → `StatusBadge`. 연체 판정은 서버 `overdue` 필드를 그대로 신뢰한다.

### ⚠ 원본 목업이 감춘 데이터 제약
원본 `LOANS` 목업은 `borrower`가 항상 채워져 있으나, 실제 서버는 **반납 완료 건의 대출자
이름을 개인정보 파기로 `null`로 내려준다**(`SearchLoansService.LoanSummary.borrowerName: String?`).
이 화면은 상태 필터 없이 전체를 받으므로 반납 건이 섞이고, 따라서 `null`이 실제로 나타난다.
→ §6 참조.

## 4. 연체 목록

원본: `DdayCard title={도서명} meta={"{대출자} · {부서} · 반납예정: {반납예정일}"} daysLeft={-경과일}`.
헤더 우측에 연체 건수 pill(빨강 solid).

### 노출 개수 = 6건 (좌측 카드 높이에 맞춤)

사용자 지시: "노출 갯수는 왼쪽의 최근 대출 활동 창의 길이랑 동일한 정도". 실제 토큰값으로 계산했다.

좌측(10행 표):
```
Card 헤더   pt-5(20) + text-xl×leading-snug(18×1.3=23.4) + pb-4(16) + border(1)  =  60.4
thead       border-y(2) + py-2.5(20) + text-sm(≈17.4)                            =  39.4
tbody 1행   py-3.5(28) + max(text-md×leading-cozy 19.6, Badge md h-5.5 22) + border(1) = 51
                                                              10행 → 510
                                                          좌측 합계 ≈ 609.8px
```

우측(카드 헤더 + `padding="md"` 본문 pt-4/pb-6 = 40):
```
리스트 가용 높이 = 609.8 − 60.4 − 40 = 509.4
DdayCard 1장 = p-4(32) + max(제목 14×normal≈20.3 + mb-0.75(3) + 메타 13×1.4=18.2 → 41.5,
                             IconBox md 40, Badge lg 26)                          = 73.5
n장 + gap-2(8) → 73.5n + 8(n−1) ≤ 509.4  →  n ≤ 6.35  →  n = 6
```
행 높이 추정을 텍스트 기준(48.6px)으로 낮춰 잡아도 `n ≤ 6.05`로 결과가 같다 → **6은 추정 오차에 견고하다.**

추가로 두 카드를 같은 grid row에 놓아 CSS로도 높이를 맞춘다(stretch) — 폰트 렌더 차이로
계산이 몇 px 어긋나도 시각적으로 어긋나지 않는다.

## 5. API (백엔드 실물 확인)

`org.library.dashboard.controller.DashboardController` — **화면 전용 집계 엔드포인트가 이미 있다.**

```
GET /dashboard/summary?recentLoanLimit=10&overdueLimit=6
→ {
    bookCount, bookItemCount, availableBookItemCount, activeLoanCount, overdueLoanCount: Long,
    recentLoans: LoanSummary[],          // 대여일 DESC, 상태 필터 없음
    overdueLoans: OverdueLoanSummary[],  // dueDate ASC = 경과일 DESC
  }
```
→ **호출 1회로 화면 전체가 채워진다.** `/books`·`/bookitems`·`/loans`를 따로 긁지 않는다.
서버가 `@Cacheable(DASHBOARD_SUMMARY, key=limit 조합)`이므로 limit을 화면에서 흔들면
캐시 키가 갈라진다 → limit은 모듈 상수로 고정한다.

`OverdueLoanSummary`(`OverdueLoansService`)는 `LoanSummary`와 다른 타입이다:
`borrowerName`이 non-null이고, `returnedAt`/`status`/`overdue`가 없으며, `overdueDays: Long`이 있다.
→ 프론트에서도 별개 타입으로 둔다(서버가 별개면 프론트도 별개 — `LoanSearchStatus` 선례).

## 6. 확정 사항 / 이탈

| 항목 | 결정 |
|------|------|
| "빠른 실행" 카드 | 제외 (사용자 지시). 4개 버튼이 전부 사이드바·관리자 탭과 중복 |
| "전체 보기" 링크 | 제외 (사용자 지시) |
| 최근 대출 10건 | 페이지네이션 없음 — `DataTable`의 `pageSize`/`serverPagination` 둘 다 미사용 |
| 연체 6건 | §4 계산. 6건 초과분은 헤더 pill의 **전체 건수**(`overdueLoanCount`)로만 드러난다 |
| "대출일" → "대여일" | 코드베이스 라벨 규칙 우선 (§3) |
| `borrowerName: null` | 목업에 없던 실제 제약. 반납 완료 건은 `—`(sr-only "파기됨")로 렌더 |
| 로딩/에러 | 카드 단위가 아니라 **화면 단위** — 호출이 1개라 카드별로 쪼개면 같은 에러가 두 번 뜬다 |
