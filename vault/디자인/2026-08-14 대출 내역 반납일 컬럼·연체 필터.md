## 대상: `LoanHistoryScreen` (디자인 소스 내 해당 화면 함수)

### 1. 표 컬럼 구성 (`cols`)

디자인 원본 그대로:

| 순서 | key | label | width | secondary | nowrap |
|---|---|---|---|---|---|
| 1 | copyNo → `managementNumber` | 관리번호 | 12% | – | ✓ |
| 2 | title → `bookTitle` | 도서명 | 20% | – | – |
| 3 | borrower → `borrowerName` | 대출자 | 9% | – | – |
| 4 | dept → `department` | 부서 | 11% | ✓ | – |
| 5 | date → `loanDate` | 대여일 | 11% | ✓ | ✓ |
| 6 | due → `dueDate` | 반납예정일 | 11% | ✓ | ✓ |
| **7 (신규)** | **returnedAt** | **반납일** | **11%** | **✗ (일반 텍스트)** | **✓** |
| 8 | status | 상태 | 9% | – | – |

**반납일 컬럼은 반납예정일과 상태 사이에 위치**하고, 부서/대여일/반납예정일과 달리 `secondary`(연한 회색)가 **아니다** — 값이 있을 때는 본문 텍스트와 동일한 진한 색(`--color-text-primary`)으로 강조된다.

디자인 폭 합계는 94%(12+20+9+11+11+11+11+9)로 100%가 아니다 — 목업 소스 오차로 보이며, 기존 프론트 컨벤션(`LOAN_COLUMNS` 폭 합 100%)을 따르도록 구현 시 비례 보정한다. 관리번호/도서명/대출자/부서/대여일/반납예정일/상태 6개 컬럼의 기존 폭 비율은 유지하고, 반납일에 새 폭을 배정하는 방식을 권장(architect 판단).

### 2. 셀 렌더링 규칙 (`renderCell`)

```
if (col.key === 'returnedAt') {
  return row.returnedAt
    ? <span style={{ color: 'var(--color-text-primary)' }}>{row.returnedAt}</span>
    : <span style={{ color: 'var(--color-text-placeholder)' }}>—</span>;
}
```

- 반납 완료 건: 실제 반납일(`YYYY-MM-DD`)을 일반 텍스트 색으로 표시
- 미반납 건(대출중/연체): **em dash `—`**를 placeholder 톤(연한 회색, 기존 코드베이스의 "값 없음" 표기와 동일 패턴)으로 표시 — 별도 아이콘·배지 없음

### 3. 상태 필터 (`StatusSelect`)

```
<option value="">전체 상태</option>
<option value="loaned">대출중</option>
<option value="overdue">연체</option>
<option value="returned">반납완료</option>
```

옵션 **순서**: 전체 상태 → 대출중 → **연체** → 반납완료. 연체는 대출중과 반납완료 사이에 삽입한다(현재 프론트 `STATUS_OPTIONS`는 전체/대출중/반납완료 2옵션뿐이므로 그 사이에 끼워 넣을 것).

디자인 목업 자체는 클라이언트 배열 필터(`status===value`)라 서버 파라미터 개념이 없다 — 실제 서버 매핑(`ALL`→생략, `ON_LOAN`/`OVERDUE`/`RETURNED`)은 이미 확보된 백엔드 스펙(`00_input/notes.md`)을 따른다. select 자체의 마크업/스타일(네이티브 `<select>` + border/radius/색상 토큰)은 기존 프론트 `LoanHistoryCard`의 `inputVariants` 기반 구현과 시각적으로 동등하므로 **변경 불필요** — 옵션 목록만 확장한다.

### 4. 상태 배지

디자인은 `<Badge status={v}/>`로 `loaned`/`overdue`/`returned` 3종을 그대로 넘긴다. 현재 프론트 `StatusBadge`/`toLoanBadgeStatus`가 이미 이 3종(`"loaned"`/`"overdue"`/`"returned"` → `BookStatus`)을 지원하고 있어(`loan-table.ts` 기존 로직) **변경 불필요**.

### 5. 변경 없음 (기존 구현 유지)

- 페이지 헤더, 검색 입력(도서명/대출자/부서 3필드), 초기화 버튼, 카드 셸, 페이지네이션, 디바운스 — 모두 기존 `LoanHistoryCard` 구현 그대로 유지. 디자인 목업은 검색 필드가 통합 검색 1개(`SearchInput` 1개)이지만, 실제 백엔드는 필드별 부분 일치 3개 파라미터(`bookTitle`/`borrowerName`/`department`)를 지원하므로 **기존 3필드 구성을 그대로 유지**한다(디자인 단순화보다 백엔드 API 능력 우선 — 기존 구현 결정 유지).

## 토큰

기존 화면이 이미 쓰는 토큰 그대로: `--color-text-primary`, `--color-text-secondary`(secondary 컬럼), `--color-text-placeholder`(빈 값 `—`). 신규 토큰 없음.
