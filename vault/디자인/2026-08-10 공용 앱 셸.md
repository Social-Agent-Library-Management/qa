# 디자인 스펙 — 공용 앱 셸

원본: `_workspace/00_input/notes.md` (Claude Design `uploads/02-dashboard.svg` DesignSync 판독)

## 레이아웃 트리

```
<html>
  <body class="flex min-h-full flex-col">      # 기존 RootLayout 유지
    <div class="flex h-screen">                 # 신규: 셸 루트 (가로 분할)
      <Sidebar activeId={derived} />             # 기존 컴포넌트, 폭 260px(w-sidebar) 고정
      <main class="flex-1 overflow-y-auto bg-canvas">
        {children}                                # 페이지별 콘텐츠 (이번 스코프 밖)
      </main>
    </div>
  </body>
</html>
```

- 사이드바 폭 260px = 기존 `--spacing-sidebar` 토큰과 일치(신규 토큰 불필요).
- 콘텐츠 영역 배경 `--color-canvas`(#F2F2F7), 사이드바 흰 배경과 대비 — 기존 토큰 재사용.
- 헤더/좌측 패딩(40px 좌우, 32px 상단)은 화면별 콘텐츠에 속하므로 이번 셸 스코프에는 넣지 않는다(후속 이슈에서 페이지가 자체 패딩 처리).

## 컴포넌트 인벤토리 (재사용/신규 후보)

| 대상 | 상태 | 비고 |
|------|------|------|
| `Sidebar` | 재사용 (수정 없음) | `src/components/library/sidebar.tsx` |
| `LIBRARY_NAV_ITEMS` | 재사용, `href` 필드만 채움 | `src/components/library/nav-items.tsx` |
| 셸 루트(사이드바+콘텐츠 분할 컨테이너) | 신규 후보 | 페이지 레이아웃에 1회만 쓰이므로 컴포넌트 추출이 필요한지 architect가 판단(README 규약: "2회 반복이면 추출") |
| activeId 계산 로직(usePathname → nav item id) | 신규 후보 | 클라이언트 훅/유틸, 위치 architect가 결정 |
| 각 화면 placeholder 페이지(도서등록/소장본등록/대출등록/반납처리/대출내역조회/연체목록) | 신규, 최소 스텁 | 실제 콘텐츠는 후속 이슈. "준비 중" 수준 |

## 상태/상호작용
- 활성 네비: 현재 라우트(pathname)와 `LIBRARY_NAV_ITEMS[].href`를 매칭해 `activeId` 결정. 루트 `/`는 `dashboard`.
- `onLogout` 등 인증 관련 prop은 이번 MVP 범위 밖 — 전달하지 않음(Sidebar가 옵션이라 자연히 로그아웃 버튼 미노출).

## 반응형
- 원본 디자인은 데스크톱 고정폭(1920) 기준. 반응형 요구사항 없음 — 이번 스코프에서 브레이크포인트 대응 안 함(기존 Sidebar도 반응형 미대응).

## 미확정 항목
- `LIBRARY_NAV_ITEMS`의 7번째 항목이 디자인 SVG("알림설정")와 기존 코드("연체목록")가 다름 — 사용자 지시("nav-items 그대로 활용")에 따라 **변경하지 않음**. QA는 이 항목을 스펙 불일치로 플래그하지 말 것(의도된 스코프 제외).
