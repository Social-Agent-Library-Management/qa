# 01. 디자인 스펙 — 소장본 등록 (`/copies/new`)

원본: Claude Design `ui_kits/library/index.html`의 `CopyRegistrationScreen` (전체 원문은 `00_input/design-url.md` 참고, orchestrator가 DesignSync `get_file`로 직접 읽음). 리더가 직접 추출 — design-interpreter 별도 호출 생략(스펙이 이미 충분히 명확하고 반복 호출 비용을 아끼기 위함).

## 범위 결정 (사용자 확인 완료)

디자인 원본에는 폼 아래에 **소장본 목록 테이블**(검색 + 상태 배지 + 분실/폐기 액션)이 있으나, 백엔드 `bookitem` 도메인에는 목록/검색 API가 없다(등록 `POST /books/{bookId}/bookitems`, 상태변경 `PATCH /bookitems/{bookItemId}/status`만 존재). 사용자에게 확인한 결과 **이번 페이지 범위에서 목록 영역은 생략**한다. 페이지는 등록 폼 카드 하나로 구성된다.

## 레이아웃 트리

```
PageHeader (title="소장본 등록", description="도서(Book)에 연결하여 실물 보유본을 등록합니다")
Card (title="새 소장본 등록")
  form
    grid grid-cols-1 sm:grid-cols-2 gap-x-6 gap-y-4
      [도서 검색 콤보박스]  label="도서명" placeholder="등록된 도서를 검색하세요" required
      Input               label="관리번호" placeholder="예: 문학-0001" hint="(주제)-(번호) 형식 · 중복 불가" required
    info row: "등록 시 초기 상태" + StatusBadge(status="available")
    actions row (justify-end): Button ghost "초기화" · Button primary "등록"(제출 중 "등록 중…")
  Toast (성공/실패)
```

기존 `BookRegisterForm`(`src/components/library/book-register-form.tsx`)과 마크업 구조·grid·버튼 배치가 동일 — 그대로 패턴 재사용.

## 반복/중복 후보

- **폼 카드 구조(Card + grid + actions row + Toast)** — `BookRegisterForm`과 100% 동일 패턴. 새로 만들지 말고 그 구조를 그대로 따른다.
- **"도서 검색 콤보박스"가 신규.** 디자인에서는 단순 텍스트 Input처럼 그려져 있지만 실제로는 `bookId`를 확정해야 `POST /books/{bookId}/bookitems`를 호출할 수 있다(백엔드가 자유 텍스트 도서명을 받지 않음). 타이핑 → `searchBooks()` 디바운스 조회 → 드롭다운에서 도서 선택 → `bookId` 확정, 텍스트는 "제목 · 저자"로 표시. 이 콤보박스는 현재 이 화면에만 필요하지만 도메인 지식 없는 범용 UI 패턴(검색형 select)이므로 `ui/` 프리미티브 + `library/` 조합 여부는 component-architect가 결정한다.
- **StatusBadge**: 디자인의 `<Badge status="available" />` → 이미 존재하는 `StatusBadge`(`status="available"` → tone success, 라벨 "대출가능")를 그대로 재사용. 신규 배지 불필요.

## 상태/상호작용

- 폼 제출 가능 조건: 도서 선택됨(`bookId != null`) **and** 관리번호 비어있지 않음. 네이티브 `required`만으로는 콤보박스의 숨은 bookId를 검증할 수 없으므로 제출 버튼 비활성화 또는 커스텀 검증 필요(구현자 판단, 기존 `BookRegisterForm`은 네이티브 required로 충분했지만 이번 필드는 다름).
- 성공: 폼 초기화(도서 선택 해제 포함), Toast(tone success, "소장본이 등록되었습니다.").
- 실패 매핑(백엔드 에러 코드 → 처리, `BookRegisterForm`의 `DUPLICATE_ISBN_CODE` 필드 에러 패턴과 동일한 방식):
  - `INVALID_MANAGEMENT_NUMBER_FORMAT` (400) → 관리번호 필드 에러
  - `DUPLICATE_MANAGEMENT_NUMBER` (409) → 관리번호 필드 에러
  - `BOOK_NOT_FOUND` (404) → 도서 콤보박스 쪽 에러(또는 토스트) — 선택 직후 도서가 삭제된 드문 경합 상황
  - 그 외/네트워크 → Toast danger
- "초기화" 버튼: 관리번호 입력값 + 도서 선택 상태 모두 초기화.

## 반응형

- `sm:grid-cols-2` 이상에서 2열, 그 아래는 1열 — `BookRegisterForm`과 동일 브레이크포인트.
- 페이지 좌우/상하 여백은 `layout.tsx`의 `<main>` 소유 — 페이지에서 재선언 금지.

## 디자인 토큰

기존 토큰으로 충분. 신규 토큰 없음(`--color-copy`/`copy` tone 이미 존재).

## 라우트

`src/app/copies/new/page.tsx` — 이미 `PagePlaceholder`로 스캐폴딩되어 있음(nav 항목 `LIBRARY_NAV_ITEMS`에 `href: "/copies/new"` 이미 연결됨, 추가 라우팅 작업 불필요). 이 페이지 구현으로 `PagePlaceholder` 사용처 1건이 사라진다(다른 화면에서 계속 쓰이므로 컴포넌트 자체는 삭제하지 않음).
