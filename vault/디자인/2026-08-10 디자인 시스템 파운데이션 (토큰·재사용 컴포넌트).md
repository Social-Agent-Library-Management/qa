# 디자인 스펙: 도서 관리 시스템 — 디자인 시스템 파운데이션 (토큰 + 8개 재사용 컴포넌트)

> **범위:** 이번 패스는 토큰 세트와 8개 재사용 컴포넌트(Button, Badge, Input, Card, StatCard, DdayCard, DataTable, Sidebar)만 다룬다. 8개 실제 화면(로그인/대시보드/도서 등록/소장본 등록/대출 등록/반납 처리/대출 내역 조회/연체·알림 설정)은 후속 이슈이며 이 스펙의 구현 대상이 아니다. 화면 조합은 "예상 조합 힌트" 섹션에서 참고용으로만 다룬다.
>
> **입력 형태:** 내보낸 React/JSX 코드(인라인 style, 참조 구현) + `.d.ts` props API + `readme.md`(디자인 원칙 서술). 코드가 있으므로 구조·props는 코드를 신뢰하고, 코드에 없는 정보(브레이크포인트, 로딩 상태 등)만 readme로 보완하거나 "미확정"으로 남긴다.

## 개요

`도서 관리 시스템`은 사회복무요원이 사용하는 도서관 관리 admin 웹앱이다(공공기관 내부용, patron 대상 화면 없음). 이 디자인 시스템은 그 admin 화면들의 시각 언어 — iOS/macOS 시스템 UI 톤(주색 `#007AFF`, 흰색/연회색 표면, 그림자 최소화, pill 배지, stroke 기반 아이콘) — 을 정의하는 토큰 세트와, 그 화면들을 조립할 8개 프리미티브/디스플레이 컴포넌트로 구성된다. 8개 컴포넌트는 core(Button/Badge/Input/Card), display(StatCard/DdayCard), data(DataTable), navigation(Sidebar) 4개 카테고리로 이미 분류되어 있으며, 이 분류는 component-architect의 파일 배치 판단에 그대로 참고할 수 있는 신호다.

## 레이아웃 트리 (컴포넌트별 내부 구조)

화면이 아닌 컴포넌트 라이브러리 입력이므로, 각 컴포넌트의 DOM/요소 중첩 구조를 옮긴다.

```
Button
└─ <button> (variant × size 스타일 조합, hover/pressed는 로컬 state로 토글)
   ├─ icon <span> (선택 — leading, flex-shrink 0)
   └─ children (라벨 텍스트)

Badge
└─ <span> pill (status → 배경/텍스트색 매핑, size별 폰트/패딩/높이)
   └─ 라벨 텍스트 (status 기본 라벨 또는 label prop으로 오버라이드)

Input
└─ <div> (column, gap 6, width 100%)
   ├─ <label> (선택 — required 시 빨간 "*" 포함)
   ├─ <input> (focus/error/disabled 상태가 border-color·box-shadow·bg에 반영)
   ├─ hint <span> (error가 없을 때만 노출)
   └─ error <span> (error 있으면 hint 대신 노출, border도 danger로 전환)

Card
└─ <div> (surface, radius-card, overflow hidden)
   ├─ header row (title prop 있을 때만 — border-bottom 1px 구분선)
   │  ├─ title <span> (18px/600)
   │  └─ titleRight (선택 — 우측 정렬 슬롯, 카운트 배지·링크 등)
   └─ content wrapper (padding: noPadding=0 / title 유무에 따라 top padding 차등)
      └─ children

StatCard
└─ <div> (flex row, gap 16, surface, radius-card, padding 20/24)
   ├─ icon circle (48×48, borderRadius 50%, iconBg 배경)
   │  └─ icon (prop으로 주입되는 SVG — 컴포넌트 자체엔 아이콘 미정의)
   └─ text block (flex:1, minWidth:0)
      ├─ label (13px, secondary color, ellipsis)
      ├─ value (28px/700, primary color)
      └─ sub (선택 — subColor로 색 오버라이드 가능, ellipsis)

DdayCard
└─ <div> (flex row, gap 12, urgency별 배경색 — daysLeft로 자동 파생)
   ├─ icon box (40×40, radius-dday, 캘린더 SVG — 컴포넌트에 하드코딩된 유일 아이콘)
   ├─ text block (flex:1) — title(ellipsis) / meta(ellipsis, secondary)
   └─ D-day pill (urgency 배경 solid, dLabel: "D-N" / "D-Day" / "D+N")

DataTable
└─ <div> wrapper
   ├─ <div style="overflow-x:auto">
   │  └─ <table>
   │     ├─ <thead> (surface-secondary bg, top/bottom border) → <th> × columns.length
   │     └─ <tbody>
   │        ├─ rows.length===0 → 빈 상태 <tr><td colSpan> emptyText
   │        └─ rows.length>0 → <tr> × N (hover bg 토글, onRowClick 있으면 pointer)
   │           └─ <td> × columns.length (renderCell로 커스텀 렌더 가능 — Badge/Button 주입 지점)
   └─ pagination footer (pageSize prop 지정 시에만 렌더)
      ├─ "총 N건 중 A–B" 텍스트
      └─ PageButton(내부 전용 서브컴포넌트) × (이전 / 숫자.../ 다음)

Sidebar
└─ <div> (260px 고정 폭, 세로 flex, 전체 높이)
   ├─ logo row (72px, border-bottom)
   │  ├─ logo icon box (40×40, primary bg, radius-logo, 인라인 4-line SVG)
   │  └─ 앱 이름 텍스트 (18px/700)
   ├─ <nav> (flex:1, overflow-y auto)
   │  └─ nav item <button> × 7 (기본 SIDEBAR_NAV_ITEMS) — active/hover/inactive 3-state
   │     ├─ Icon (item별 인라인 SVG 컴포넌트, color prop으로 상태색 주입)
   │     └─ label <span>
   └─ user footer (border-top, padding 14/20)
      ├─ avatar circle (36×36, 이니셜 "관" 텍스트)
      ├─ 텍스트 블록 (name 14px/600, email 12px secondary ellipsis)
      └─ logout <button> (onLogout prop 있을 때만 렌더, 아이콘 전용)
```

### 예상 조합 힌트 (참고용 — 화면 자체는 범위 밖)

readme의 Visual Foundations 서술 기준 추정:
- **공통 셸:** `Sidebar`(좌측 고정 260px) + 우측 `main`(배경 `--color-bg`, padding `--space-page-x`/`--space-page-y`) — 8개 화면 전부 공통.
- **대시보드:** `main` 상단에 `StatCard` 반복(3~4개, 가로 flex row), 하단은 2열 — 좌측 넓은 `Card`(제목+`DataTable`), 우측 좁은 `Card`(제목+`DdayCard` 반복 리스트, 반납 임박 알림).
- **도서/소장본/대출 등록:** `Card`(폼 컨테이너) 안에 `Input` 반복(N개) + 하단 `Button` 쌍(ghost "초기화" + primary "등록").
- **대출 내역 조회 / 연체 목록:** `Card`(noPadding 또는 padding 최소) + `DataTable`(pageSize 지정, `renderCell`로 `Badge` 상태 컬럼 주입).
- **로그인:** 유일하게 `--shadow-login` 사용 추정(readme: "only the login card uses a visible shadow") — `Card`류가 아닌 별도 로그인 전용 카드일 가능성.
- **알림 설정:** `DdayCard` 패턴 재사용 + 폼 요소(Input) 조합 추정.

이 문단은 전부 "추정"이며 실제 8개 화면 스펙 작업 시 재검증 필요.

### 그림자 (`tokens/shadows.css`)

| 토큰 | 값 | 사용 여부(8개 컴포넌트 기준) |
|---|---|---|
| `--shadow-sm` | `0 1px 3px rgba(0,0,0,.06), 0 1px 2px rgba(0,0,0,.04)` | 미사용 |
| `--shadow-md` | `0 4px 12px rgba(0,0,0,.08), 0 2px 4px rgba(0,0,0,.04)` | 미사용 |
| `--shadow-lg` | `0 8px 24px rgba(0,0,0,.10), 0 4px 8px rgba(0,0,0,.06)` | 미사용 |
| `--shadow-card` | `0 2px 8px rgba(0,0,0,.06)` | 미사용 — Card는 명시적으로 그림자 없음(readme: "No drop shadows") |
| `--shadow-login` | `0 8px 40px rgba(0,0,0,.12)` | 8개 컴포넌트 미사용 — 로그인 화면(범위 밖) 전용으로 readme에 명시 |
| `--shadow-dropdown` | `0 4px 16px rgba(0,0,0,.10), 0 1px 4px rgba(0,0,0,.06)` | 8개 컴포넌트 미사용 — 향후 드롭다운/모달용 |

**결론: 현재 8개 컴포넌트는 그림자 토큰을 하나도 사용하지 않는다.** 이는 실수가 아니라 readme의 의도된 원칙("Shadows: Minimal — only the login card uses a visible shadow")이다. 구현 시 임의로 그림자를 추가하지 말 것.

Input의 focus ring(`0 0 0 3px rgba(0,122,255,0.12)`)은 `--shadow-*` 토큰 세트에 없는 별도 하드코딩 값 — 재사용 가능성이 높으므로(향후 select/textarea/search 등도 동일 링 필요) `--shadow-focus-ring` 같은 토큰화를 구현 단계에서 고려할 것(신규 제안, 원본에는 없음).

## 컴포넌트 인벤토리

| 컴포넌트 | 카테고리 | 설명 | 반복(정적 인스턴스 기준) | 중복 후보 | variant/상태 힌트 |
|---|---|---|---|---|---|
| Button | core | 폼 제출/CTA/액션 트리거 | 화면마다 다수(범위 밖) | — (기준 컴포넌트 자체) | variant 5종(primary/secondary/ghost/danger/success) × size 3종(sm/md/lg) × disabled/fullWidth/icon |
| Badge | core | 대출/소장 상태 pill 라벨 | 화면마다 다수 | **예** — DdayCard의 D-day pill과 시각 패턴(pill 배경+텍스트) 동일하나 별도 구현 | status 7종(available/loaned/overdue/returned/lost/disposed/copy — readme 서술은 5종만 언급, 아래 미확정 참고) × size 3종 |
| Input | core | 라벨+포커스링+에러/힌트 텍스트필드 | 화면마다 다수(폼 화면) | 낮음(독립적) | focus/error/disabled/hint, required |
| Card | core | 흰 표면 컨테이너(제목+구분선 헤더 선택) | 화면마다 다수 | 낮음(래퍼 성격) | title 유무, padding 3단(sm/md/lg), noPadding |
| StatCard | display | 대시보드 KPI 카드(아이콘+큰 숫자+서브텍스트) | 대시보드에서 3~4회(추정, 범위 밖) | **예** — 아이콘 원형 컨테이너(48px, iconBg) 패턴이 DdayCard의 아이콘 박스(40px, iconBg)와 "컬러 배경 + 중앙 아이콘" 구조를 공유(circle vs rounded-square 차이만) |
| DdayCard | display | 반납 임박 알림 행 카드(urgency 자동 색상) | 알림 패널에서 N회 반복(추정, 범위 밖) | **예** (Badge, StatCard와 각각 중복 — 아래 참고) | urgency 3단(urgent/warning/normal, daysLeft로 자동 파생) |
| DataTable | data | 정렬/hover/페이지네이션 포함 테이블 | 화면당 1개, 행은 다수 | **예** — 내부 `PageButton` 서브컴포넌트가 Button과 별개로 active/disabled 시각 패턴을 재구현 | columns/rows/renderCell/pageSize/onRowClick, 빈 상태 |
| Sidebar | navigation | 260px 고정 좌측 네비 + 유저 푸터 | 전 화면 공통 1개 | **예** — nav item의 hover/active 배경 토글 로직이 Button, DataTable row, PageButton과 동일한 "로컬 state로 배경색 스위칭" 패턴을 각자 재구현 | items 오버라이드, activeId, onLogout 유무 |

### 발견한 중복/일관성 후보 (component-architect 우선 검토 대상)

1. **Hover/pressed 인터랙션 패턴 4중 중복** — Button(hover+pressed), Sidebar nav item(hover), DataTable row(hover), DataTable 내부 PageButton(active/disabled)이 각각 독립적으로 `useState`로 hover/pressed를 추적해 배경색을 스위칭한다. Tailwind v4로 옮기면 이 중 상당수는 JS state 없이 `:hover`/`:active` 클래스만으로 대체 가능 — 실구현 시 상태 관리 자체가 사라지고 스타일 매핑만 남을 가능성이 높다. component-architect는 "이 4곳이 같은 인터랙션 프리미티브를 쓸 수 있는가"를 판단할 것.
2. **Pill 배지 시각 패턴 이중 구현** — Badge(범용 status pill)와 DdayCard의 D-day 카운트 pill이 형태(radius-full, 컬러 배경+텍스트)는 동일하지만 완전히 별개 코드다. DdayCard가 Badge를 합성(예: `variant="urgency"` 또는 색상 override 가능한 Badge)해서 쓸 수 있는지 검토 대상.
3. **아이콘 컨테이너 패턴 이중 구현** — StatCard의 48px 원형 아이콘 배경과 DdayCard의 40px 라운드사각 아이콘 배경이 "컬러 배경 박스 + 중앙 정렬 아이콘"이라는 동일 구조를 shape/size만 다르게 재구현. 공유 `IconContainer`(shape: circle|square, size, bg) 프리미티브 후보.
4. **DataTable의 PageButton이 Button을 재사용하지 않음** — 크기(30px height)·radius·active/disabled 톤이 Button과 근접하지만 Button을 합성하지 않고 새로 작성됨. Button에 pagination에 맞는 극소형(xs) 사이즈 + active 상태를 추가해 흡수할 수 있는지 검토.
5. **반경/색 토큰 미참조 하드코딩** — Sidebar nav item의 `borderRadius: 8`(→`--radius-button`), StatCard/Sidebar 아바타의 `'50%'`(→`--radius-full`), Badge `loaned` 상태의 배경 하드코딩 `#FFF0D6`(→`--color-warning-light`)는 값은 토큰과 동일하지만 변수 참조가 아니다. Tailwind 구현 시 자연히 유틸리티 클래스로 정규화되겠지만, 변환 과정에서 값 불일치가 생기지 않도록 명시.
6. **DataTable `PageButton`의 fallback 불일치** — `var(--radius-sm, 6px)`의 폴백(6px)이 실제 `--radius-sm` 토큰값(4px)과 다르다. 토큰이 항상 정의되어 있으므로 런타임 영향은 없지만, 구현자가 그대로 베끼면 혼란의 소지 — 실구현 시 `--radius-sm`(4px) 또는 별도 결정값으로 명확히 할 것.

## 상태 & 상호작용

| 컴포넌트 | 상태/동작 | 내용 |
|---|---|---|
| Button | hover | 비활성 아님 && hover 시 `variant.hoverBg`로 배경 전환 |
| | pressed | mousedown~mouseup 동안 `transform: scale(0.97)` |
| | disabled | `opacity: 0.42`, `cursor: not-allowed`, hover/pressed 무시 |
| | focus | **미확정** — `outline: none`이며 대체 focus-visible 스타일이 코드에 없음(접근성 갭, 실구현 시 보완 필요) |
| | 클릭 | `onClick` 호출, `type` prop으로 submit/reset 겸용 |
| Badge | 상태 없음 | 순수 표시용, 인터랙션 없음 |
| Input | focus | border → primary색 + `box-shadow: 0 0 0 3px rgba(0,122,255,.12)` (error 상태면 링 생략) |
| | error | border → danger색, `error` 텍스트가 `hint`를 대체 |
| | disabled | 배경 `surface-secondary`, `opacity: .55`, `cursor: not-allowed` |
| | hint | error 없을 때만 노출되는 보조 텍스트 |
| Card | 상태 없음 | 정적 컨테이너. `title` 유무로 헤더 렌더 여부만 분기 |
| StatCard | 상태 없음 | 정적 표시. onClick 등 인터랙션 props 자체가 없음(순수 display) |
| DdayCard | 파생 상태(자동) | `daysLeft`로 urgency 자동 계산 — `≤0` 또는 `≤2` → urgent(빨강), `3~5` → warning(주황), `6+` → normal(회색). 사용자 인터랙션 없음(클릭 핸들러 없음) |
| DataTable | row hover | 배경 `surface-secondary` 토글 |
| | row 클릭 | `onRowClick` 있으면 pointer 커서 + 클릭 시 `(row, index)` 콜백 |
| | 빈 상태 | `rows.length === 0` → `emptyText`(기본 "데이터가 없습니다.") 중앙 정렬 표시 |
| | 로딩 상태 | **미확정** — `isLoading` 류 prop이 없음. 실사용 화면에서 로딩 스피너/스켈레톤이 필요하면 DataTable 외부에서 조건 렌더해야 함 |
| | pagination | `pageSize` 지정 시에만 렌더. 페이지 버튼 active/disabled 상태, "이전/다음" 경계 처리, 7페이지 초과 시 "…" 생략 표기 |
| Sidebar | nav item hover | 비활성 항목만 `--color-bg` 배경 hover(활성 항목은 hover 무시) |
| | nav item active | `activeId` 일치 시 `--color-primary-light` 배경 + primary색 아이콘/라벨(semibold) |
| | 클릭 | `onSelect(id)` 콜백 — 라우팅은 컴포넌트 책임 밖(상위에서 처리 추정) |
| | 로그아웃 | `onLogout` prop이 있을 때만 로그아웃 아이콘 버튼 렌더(조건부 노출) |
| | 반응형/모바일 축소 | **미확정** — 사이드바는 260px 고정폭만 정의, 접힘/오버레이 모드 없음(아래 반응형 규칙 참고) |

## 반응형 규칙

**미확정 — 브레이크포인트 토큰 자체가 정의되어 있지 않다.** `tokens/` 디렉터리에 `breakpoints.css` 또는 이에 준하는 파일이 없고, 8개 컴포넌트 코드 어디에도 미디어쿼리나 반응형 분기가 없다. readme의 Caveats 섹션은 "Single product: 관리자용 웹앱 하나뿐, 모바일 앱/공개 포털 없음"이라고 명시하며, Sidebar는 260px 고정폭 + `flexShrink: 0`으로 항상 표시되는 것을 전제로 만들어져 있다.

이것이 "반응형이 필요 없다"는 확정 스펙인지, 아니면 "이번 SVG 드래프트 소스에 반응형이 없었을 뿐"인지는 readme만으로 판단 불가 — **사용자 확인 필요**. component-architect/frontend-implementer는 우선 데스크톱 전용으로 구현하되, 최소 지원 해상도(예: 1280px 이상만 지원?) 확인을 사용자에게 요청할 것을 권장.

## 데이터/콘텐츠 형태

각 컴포넌트의 `.d.ts`가 신뢰 가능한 props API이므로 그대로 타입 소스로 채택한다.

```ts
// Button
interface ButtonProps {
  variant?: 'primary' | 'secondary' | 'ghost' | 'danger' | 'success'; // default 'primary'
  size?: 'sm' | 'md' | 'lg'; // default 'md'
  disabled?: boolean;
  fullWidth?: boolean;
  onClick?: () => void;
  type?: 'button' | 'submit' | 'reset';
  icon?: React.ReactNode;
  children: React.ReactNode;
}

// Badge
interface BadgeProps {
  status?: 'available' | 'loaned' | 'overdue' | 'returned' | 'lost' | 'disposed' | 'copy'; // default 'available'
  label?: string; // status 기본 라벨 오버라이드
  size?: 'sm' | 'md' | 'lg'; // default 'md'
}

// Input
interface InputProps {
  label?: string;
  placeholder?: string;
  required?: boolean;
  value?: string;
  onChange?: (e: React.ChangeEvent<HTMLInputElement>) => void;
  type?: string;
  disabled?: boolean;
  hint?: string;
  error?: string;
  id?: string;
}

// Card
interface CardProps {
  children: React.ReactNode;
  title?: string;
  titleRight?: React.ReactNode;
  padding?: 'sm' | 'md' | 'lg'; // default 'md'
  noPadding?: boolean;
  style?: React.CSSProperties;
}

// StatCard
interface StatCardProps {
  label: string;      // 예: "전체 도서"
  value: string | number; // 예: "1,247"
  sub?: string;        // 예: "+12 이번 달"
  subColor?: string;
  iconBg?: string;
  icon?: React.ReactNode;
}

// DdayCard
interface DdayCardProps {
  title: string;   // 도서명
  meta: string;     // "대출자 · 부서 · 반납예정일" 조합 문자열(단일 필드 — 구조화되어 있지 않음)
  daysLeft: number;  // 음수 = 연체
}

// DataTable
interface DataTableColumn {
  key: string;
  label: string;
  width?: string;
  nowrap?: boolean;
  secondary?: boolean;
}
interface DataTableProps {
  columns: DataTableColumn[];
  rows: Array<Record<string, any>>;
  renderCell?: (column: DataTableColumn, value: any, row: Record<string, any>) => React.ReactNode;
  emptyText?: string; // default '데이터가 없습니다.'
  onRowClick?: (row: Record<string, any>, index: number) => void;
  pageSize?: number;
}

// Sidebar
interface SidebarNavItem {
  id: string;
  label: string;
  Icon?: React.ComponentType<{ color: string }>;
}
interface SidebarUser {
  name: string;
  email: string;
}
interface SidebarProps {
  items?: SidebarNavItem[]; // 기본값 SIDEBAR_NAV_ITEMS(7개)
  activeId?: string; // default 'dashboard'
  onSelect?: (id: string) => void;
  user?: SidebarUser; // default { name: '관리자', email: 'admin@library.go.kr' }
  onLogout?: () => void;
}
```

`DdayCard.meta`가 "대출자 · 부서 · 반납예정일"을 이미 조합된 단일 문자열로 받는 점은 주목할 것 — 실제 화면에서 이 조합 포맷팅(구분자 `·`, 순서)을 어디서 하는지는 화면 스펙(범위 밖)에서 확정 필요.

## 아이코노그래피 규칙

readme Iconography 섹션과 `Sidebar.jsx`의 실제 인라인 SVG 정의를 대조한 결과다.

**공통 규칙(readme 기준, 확인됨):**
- 커스텀 인라인 SVG만 사용 — 아이콘 폰트·서드파티 아이콘 라이브러리·이모지·유니코드 대체 없음
- Stroke 기반, `fill="none"`, `strokeLinecap: round`
- 내비게이션 아이콘: 20×20 viewBox, 1.5px stroke — **코드로 확인됨**(Sidebar 내 7개 아이콘 전부 `width/height=20`, `viewBox="0 0 20 20"`, `strokeWidth="1.5"`)
- 모노크롬 — 비활성 `#8E8E93`(text-secondary), 활성/주요 `#007AFF`(primary) — **코드로 확인됨**(Sidebar가 `color` prop을 아이콘에 그대로 주입)
- 폼 아이콘(예: 비밀번호 눈 아이콘): 20×20, 1.5px stroke — 8개 컴포넌트 범위에는 해당 아이콘 자체가 없음(로그인 화면, 범위 밖)

**Sidebar.jsx에 정의된 아이콘 인벤토리 (실제 코드 기준, 총 8개 — nav 7개 + logout 1개):**

| 함수명 | 대응 nav id | 라벨 | 형태 요약 |
|---|---|---|---|
| `IconDashboard` | dashboard | 대시보드 | 4분할 사각형 그리드 |
| `IconBook` | book-register | 도서 등록 | 책등 있는 펼친 책 |
| `IconCopy` | copy-register | 소장본 등록 | 겹친 페이지(스택) |
| `IconLoan` | loan-register | 대출 등록 | 건물 형태 + 하향 화살표 느낌 |
| `IconReturn` | return | 반납 처리 | 원형 화살표(반시계) |
| `IconHistory` | loan-history | 대출 내역 조회 | 시계(원 + 바늘) |
| `IconOverdue` | overdue | 연체 목록 | 원 + 느낌표(경고 아이콘) |
| `IconLogout` | (nav 아님, 유저 푸터 전용) | — | 16×16, 문 밖으로 화살표 |

**readme 서술과 코드 간 불일치 — 미확정 항목으로 아래에 재기재:**
1. readme는 7번째 아이콘을 "Notification (bell)"이라 서술하지만, 실제 코드의 7번째 nav 아이템은 `overdue`(연체 목록, 느낌표 원형 아이콘)이며 벨 모양 SVG는 어디에도 정의되어 있지 않다.
2. readme Iconography 섹션은 로고 마크를 "26×26 inside 48×48 container, 2.2px stroke"라 서술하지만, Visual Foundations 섹션과 실제 코드는 "40×40 container(`--radius-logo` 10px), 22×22 SVG, 2px stroke"로 일치한다 — Iconography 섹션 쪽 수치가 readme 자체 내에서도 모순.
3. `IconLogout`은 readme Iconography 섹션에 언급이 없는 8번째 인라인 아이콘이다.

**스탯카드 아이콘:** StatCard는 아이콘을 prop으로 주입받을 뿐 컴포넌트 자체에 아이콘을 정의하지 않는다. readme는 "24×24, 1.5–2px stroke, 48px 원 안"이라 명시하나 이는 가이드일 뿐 코드로 강제되지 않음 — 소비자(화면 구현체)가 규칙을 지켜야 한다.

## 미확정 항목 (확인 필요)

1. **Badge 상태 개수 불일치** — readme Visual Foundations는 "Five statuses: 대출가능/대출중/연체/반납완료/소장본"이라 명시하지만, `Badge.jsx`의 `STATUS_CONFIG`에는 `lost`(분실)와 `disposed`(폐기)가 추가되어 총 7종이다. 이 2종이 의도된 추가 사양인지, readme가 최신화되지 않은 것인지 사용자 확인 필요.
2. **Sidebar 7번째 아이콘 정체성** — readme는 "Notification(bell)"이라 서술하나 실제 코드는 "연체 목록"(`IconOverdue`, 느낌표 아이콘)이다. 실제 8번째 화면이 "연체/알림 설정"으로 명명된 것과도 미묘히 다름(`overdue` vs `notification-settings`). 최종 네비게이션 라벨/아이콘/화면 매핑을 사용자에게 확인 필요.
3. **로고 마크 치수 readme 내부 모순** — 위 아이코노그래피 섹션 참고. 실구현은 코드값(40×40/22×22/2px)을 신뢰하되, 사용자에게 재확인 권장.
4. **반응형 브레이크포인트 전무** — 토큰/코드 어디에도 정의 없음. 데스크톱 전용 확정인지, 최소 지원 해상도가 있는지 확인 필요.
5. **Button focus-visible 스타일 부재** — `outline: none`만 있고 대체 포커스 인디케이터가 없어 키보드 접근성 갭. 실구현 시 보완 필요(디자인 의도인지 누락인지 불명).
6. **DataTable 로딩/에러 상태 부재** — `isLoading`/`error` 유사 prop이 없음. 실제 화면에서 API 로딩·실패를 어떻게 표현할지 별도 확인 필요(범위 밖 화면 작업 시 해결될 가능성 높음, 지금은 기록만).
7. **DdayCard.meta 포맷 미구조화** — "대출자 · 부서 · 반납예정일"이 단일 문자열 prop. 실제 데이터가 이렇게 사전 조합되어 오는지, 아니면 화면단에서 조합하는지 확인 필요.
8. **토큰 미참조 하드코딩 다수** — 컴포넌트 인벤토리의 "발견한 중복/일관성 후보" 5–6번 항목(색/반경 리터럴, PageButton radius-sm 폴백 불일치)은 실구현(Tailwind 유틸리티화) 과정에서 자연히 정규화될 여지가 크지만, 원본 값과 다르게 변환되지 않도록 구현자가 주의해야 함.
9. **그림자 토큰 6종 중 8개 컴포넌트에서 실사용 0건** — 의도된 미니멀리즘(readme 확인)이지만, 향후 모달/드롭다운/로그인 화면(범위 밖) 작업 때 처음 사용될 것이라는 점을 인지만 해둘 것.

## component-architect 전달 요약

- **디자인 토큰:** 색상 21종 + 시맨틱 alias, 타이포(크기 9 / 굵기 4 / 자간 2), 스페이싱 11(4px 그리드) + 시맨틱 alias 9, 반경 5 + 시맨틱 alias 7, 그림자 6(현재 0건 사용) — 전부 `tokens/*.css` → 향후 `globals.css`의 `@theme`로 이관 대상.
- **컴포넌트 8개, 중복 후보 6건**(위 "발견한 중복/일관성 후보" 목록) — 특히 **① hover/pressed 인터랙션 4중 중복**, **② Badge ↔ DdayCard pill 배지 이중 구현**, **③ StatCard ↔ DdayCard 아이콘 컨테이너 이중 구현**, **④ DataTable PageButton이 Button 미재사용** 은 재사용 설계의 핵심 출발점이니 우선 검토 요청.
- **미확정 9건** 중 1~3번(Badge 상태 개수, 7번째 아이콘 정체성, 로고 치수)은 원본 소스(readme) 자체의 내적 모순이라 사용자 확인 없이는 구현팀이 임의로 정할 수 없는 항목 — 리더를 통해 사용자 확인 요청 권장.
