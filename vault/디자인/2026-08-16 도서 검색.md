# 디자인 스펙: 도서 검색 화면 (`BookSearchScreen`, `#23`)

## 개요

도서명·저자·출판사·ISBN으로 도서를 검색하고, 검색 결과 표에서 행을 클릭하면 우측 패널에
해당 도서의 소장본(실물 사본) 목록이 나타나는 2단 레이아웃 화면이다. Claude Design
`ui_kits/library/index.html`의 `BookSearchScreen` 컴포넌트가 원본이며, `App`의
`SCREENS['book-search']`로 등록되어 있으나 `ui_kits/library/README.md`에는 누락되어 있다(문서
stale — 화면 자체는 실존).

**이 스펙은 원본 디자인을 그대로 옮기지 않는다.** 사용자가 명시한 두 가지 제약을 반영해 원본
대비 컬럼을 축소했다 — 백엔드 `GET /books/{id}` 응답과 `GET /books/search` 응답에 원본 mock
데이터(`LOANS`, `BOOKS`)가 가진 대출자·반납예정일·상태별 세부 카운트 필드가 없기 때문이다.
상세는 아래 컴포넌트 인벤토리·데이터 형태 절 참조.

이 화면은 신규 라우트(`/books/search`)이며 사이드바 내비게이션에 항목이 없어 추가가 필요하다.

## 레이아웃 트리

```
Page (도서 검색) — 좌우/상하 여백은 src/app/layout.tsx <main>이 소유, 페이지에서 재적용 금지
├─ PageHeader
│    title="도서 검색"
│    description="도서를 검색하고 행을 선택하면 소장본 목록이 표시됩니다"
├─ SearchBar Card (padding="sm", 하단 여백)
│    └─ Row (flex, gap 10 / 모바일 세로 스택 검토)
│       ├─ SearchInput (아이콘 + 텍스트 입력)
│       │    placeholder="도서명, 저자, 출판사, ISBN 검색"
│       │    leading icon: IconSearch(신규)
│       └─ Button variant="ghost" size="sm" — "초기화"
└─ ResultArea (flex, flex-wrap, gap 20)
   ├─ 좌: Card  ["검색 결과" 패널]
   │     title="검색 결과"
   │     titleRight=CountBadge(총 건수, 예: "12건")
   │     noPadding, flex-basis "2 1 520px"
   │     └─ DataTable (좌측 결과 표)
   │          columns: 도서명 / 저자 / 출판사 / ISBN / 소장본(총 소장본 수만)
   │          onRowClick → 선택 상태 갱신
   │          renderCell: 선택된 행의 "도서명" 셀만 primary색 + semibold 강조
   │          emptyText="검색 결과가 없습니다."
   └─ 우: Card  ["소장본" 패널 — 선택 여부로 콘텐츠 분기]
         title = 선택 있음 → "소장본 · {도서명}" / 선택 없음 → "소장본 목록"
         titleRight = 선택 있음 → CountBadge(소장본 건수, tone=copy) / 없음 → null
         noPadding, flex-basis "1 1 400px"
         ├─ [선택 없음] EmptyState
         │     텍스트: "왼쪽 목록에서 도서를 선택하세요."
         │     중앙 정렬, 세로 여백 큼(56px), placeholder 톤
         └─ [선택 있음]
            ├─ MetaRow (구분선 아래, flex-wrap, gap 20)
            │     "저자 {author}" / "출판사 {publisher}" / "ISBN {isbn}"
            │     라벨은 보조색, 값은 semibold 강조
            └─ DataTable (우측 소장본 표)
                 columns: 관리번호 / 상태  ← 원본 4컬럼에서 2컬럼으로 축소(제약 ①)
                 renderCell: "상태" 컬럼 → StatusBadge
                 emptyText="등록된 소장본이 없습니다."
```

## 디자인 토큰 매핑

원본 인라인 스타일(`var(--color-*)`, px 값)을 `src/app/globals.css`의 기존 `@theme` 토큰에
매핑한다. 신규 토큰은 필요하지 않다 — 전부 기존 토큰/기본 스페이싱 스케일로 표현 가능하다.

| 원본 값 | 매핑 토큰 | 비고 |
|---|---|---|
| `var(--color-border)` (SearchInput 테두리) | `border-line` | globals.css가 이미 원본 `--color-border`→`--color-line`로 통일 |
| `var(--color-bg)` (SearchInput 배경) | ~~`bg-canvas`~~ → **`bg-surface`(확정 아님, 아래 참조)** | 원본 문자 그대로면 canvas지만, 기존 `ui/Input`은 전부 `bg-surface`를 쓴다(디자인 미확정 항목 참조) |
| `var(--color-text-primary)` | `text-fg` | |
| `var(--color-text-secondary)` (MetaRow 라벨, 소장본 컬럼 보조 텍스트) | `text-fg-muted` | |
| `var(--color-text-placeholder)` (빈 상태 문구, `—`) | `text-fg-subtle` | |
| `var(--color-primary)` / `var(--color-primary-light)` (CountBadge 기본, 선택 행 강조) | `text-primary` / `bg-primary-light` (`Badge tone="neutral"`은 실제로는 아래 참고) | 좌측 CountBadge는 기존 `BookListCard`/`LoanHistoryCard` 선례처럼 `tone="neutral"` 사용이 일관적(원본 `CountBadge` 기본 color prop은 primary였지만 두 선례 모두 neutral) — **미확정 항목 참조** |
| `var(--color-copy)` / `var(--color-copy-light)` (우측 CountBadge) | `Badge tone="copy"` | 기존 `badgeVariants`에 이미 존재하는 tone, 그대로 확정 매핑 |

| 폰트 크기 12px (MetaRow, CountBadge) | `text-sm` | |
| 폰트 크기 13px (empty state, 소장본 컬럼 원본 값) | `text-base` | |

| radius 12px (Card) | `rounded-card` | 기존 `Card`가 이미 적용 |

| gap 10px (검색바 row) | `gap-2.5` | 4px 그리드 기본값, 커스텀 토큰 불필요 |
| gap 20px (2단 레이아웃, MetaRow) | `gap-5` | 4px 그리드 기본값 |
| padding 12px 20px (MetaRow) | `py-3 px-5` | 4px 그리드 기본값 |

## 컴포넌트 인벤토리

이 화면 안에서의 반복(중복 후보)과, 화면을 넘어선 기존 코드베이스 대비 중복(재사용 후보)을
분리해서 기록한다. 후자가 이 스펙에서 가장 중요한 산출물이다 — 아래 "재사용 후보" 절 참조.

| 컴포넌트 | 설명 | 반복(화면 내) | 중복 후보 | variant 힌트 |
|---|---|---|---|---|
| `Card` | 검색바 / 좌 결과 / 우 소장본 컨테이너 | 3 | 예 — 신규 아님, 기존 `ui/Card` 그대로 | `padding="sm"`(검색바) / `noPadding` + `title`(결과·소장본) |
| `DataTable` | 좌측 검색 결과 표, 우측 소장본 표 | 2 | 예 — 신규 아님, 기존 `ui/DataTable` 그대로 | 좌: `onRowClick`+`renderCell`(선택 강조) / 우: `renderCell`(StatusBadge) |
| `Badge`(원본 `CountBadge` 대응) | 건수 배지 | 2 | 예 — 원본의 `CountBadge`는 신규 컴포넌트가 아니라 기존 `ui/Badge`(`variant="soft"`)로 정확히 대체된다 | `tone="neutral"`(좌) / `tone="copy"`(우, 선택 시) |
| `Button` | "초기화" 고스트 버튼 | 1 | 아니오 — 기존 `ui/Button` 그대로 | `variant="ghost"` `size="sm"` |
| `SearchInput`(원본 커스텀) | 검색어 입력 + 좌측 돋보기 아이콘 | 1 | **애매 — 판단 필요.** 기존 `ui/Input`엔 leading-icon 슬롯이 없다(`Button`만 `icon` prop 보유). 신규 프리미티브를 만들지, `Input`에 `icon` prop을 확장할지, 화면 로컬 조합(relative wrapper + 절대배치 아이콘)으로 둘지는 component-architect 판단 대상 | — |
| `PageHeader` | 상단 타이틀 | 1 | 아니오 — 기존 `ui/PageHeader` 그대로 | — |
| `StatusBadge` | 소장본 상태 배지 | 소장본 행 수만큼(가변) | 아니오 — 기존 `library/StatusBadge` 그대로. `BookItemStatus`(`AVAILABLE`/`ON_LOAN`/`LOST`/`DISPOSED`) 4값 전부 이미 매핑 범위(`available`/`loaned`/`lost`/`disposed`)에 포함되어 있음을 소스 확인함(확장 불필요) | `status` prop만 |
| `ListErrorState` | 좌측 검색 실패 / 우측 상세 조회 실패 | 최대 2 | 예 — 기존 `ui/ListErrorState` 그대로 | — |
| `IconSearch`(신규) | 검색 입력창 아이콘 | 등록 1회 | 신규 — `icons/` 컨벤션(`IconBase` 합성)에 맞춰 추가. 아래 미확정 항목 참조 | — |
| `BookSearchCard`(가칭, 신규 도메인 컴포넌트) | 검색바+좌측 결과 표(또는 화면 전체)를 묶는 카드형 컴포넌트 | 신규 1 | **강한 재사용 후보** — `LoanHistoryCard`(검색+디바운스+DataTable+선택/필터)와 골격이 거의 동일. 아래 "재사용 후보" 절 참조 | — |
| `BookDetailPanel`(가칭, 신규 도메인 컴포넌트) | 우측 소장본 패널(선택 전/후 분기, 상세 조회) | 신규 1 | 신규 — 기존 화면에 선례 없음(선택 기반 상세 패널은 이 화면이 최초) | — |
| `book-table.ts`(가칭, 신규) | 좌측 결과 컬럼 정의 + 우측 소장본 컬럼 정의 | — | **강한 재사용 후보** — `library/loan-table.ts` 선례(컬럼 공유 파일 분리)와 동일 패턴. 아래 절 참조 | — |

## 재사용 후보 (기존 코드베이스 대비 — component-architect 필독)

`_workspace/00_input/design-source.txt`에 이미 조사되어 있는 재사용 후보를 그대로 인용한다.
다음 단계(중복 제거 설계)의 출발점이다.

- **`src/components/library/book-list-card.tsx`(`BookListCard`)** — `BOOK_COLUMNS`(도서명 28% /
  저자 14% / 출판사 16%,secondary / ISBN 20%,secondary,nowrap / 소장본 수 10%) + `searchBooks`
  배선 + `serverPagination` + `ListErrorState` 패턴을 이미 갖고 있다. 이번 화면 좌측 "검색 결과"
  표와 컬럼 구성이 **거의 동일**하지만, `BookListCard`엔 검색어 입력·행 클릭·선택 상태가 없어
  컴포넌트 자체의 재사용은 불가하다. **컬럼 정의만** 공유할지(`book-table.ts` 분리) 여부가
  판단 대상.
- **`src/components/library/loan-history-card.tsx`(`LoanHistoryCard`)** — 검색어 상태 +
  `useDebouncedValue` + 서버 필터 + `serverPagination` + `ListErrorState` + `Card`/`Badge`
  조합의 선례. 이번 화면의 좌측 "검색 결과" 영역(검색 입력 → 필터링된 DataTable, 선택 상태
  포함)이 이 카드와 **구조적으로 매우 유사**하다 — "반복 패턴"으로 강조 표시한다. 다만
  `LoanHistoryCard`는 필터 3종 + select이고 이 화면은 통합 검색어 1종 + 행 선택이라는 점에서
  차이가 있다.
- **`src/components/library/status-badge.tsx`(`StatusBadge`)** — 상태 → (tone, 한글 라벨) 매핑이
  이미 `BookItemStatus` 4값 전부를 포함한다(위 컴포넌트 인벤토리 표 확인 완료). 신규 매핑 불필요,
  그대로 재사용.
- **`src/components/library/loan-table.ts`** — 컬럼 정의를 화면 파일에서 반복하지 않고 별도
  파일로 소유시킨 선례(`LOAN_COLUMNS`/`LOAN_HISTORY_COLUMNS`). 이번 화면도 좌측 결과 컬럼과
  우측 소장본 컬럼을 `book-table.ts` 같은 파일로 분리할지 검토할 근거로 인용한다.
- **`src/lib/use-debounced-value.ts`** — 검색 입력 디바운스에 재사용 검토 대상(원본 디자인은
  즉시 클라이언트 필터링이지만, 실 구현은 서버 검색이므로 디바운스가 맞다).
- **`src/lib/api/bookitems.ts`의 `BookItemStatus` 타입** — 신규 `getBook()` 응답 타입을 정의할
  때 이 타입을 재사용해야 한다(재정의 금지). `BookItem`(`bookItemId`/`bookId`/
  `managementNumber`/`status`/`createdAt`)과 신규 `BookItemSummary`(`bookId` 없음)도 구조가
  거의 같다는 점을 확인함 — 완전 별도 타입으로 새로 정의하기보다 관계를 명시할 것.
- **`src/components/README.md`의 "합성 관계" 섹션** — `BookListCard`/`LoanHistoryCard`/
  `ListErrorState`/`loan-table.ts` 관련 조항 필독. 특히 "목록 조회 실패 UI를 카드마다 다시
  마크업하지 말 것", "디바운스를 컴포넌트에 인라인하지 말 것" 조항이 이 화면에도 그대로
  적용된다.

## 상태 & 상호작용

| 요소 | 상태/동작 |
|---|---|
| 검색 입력 | 값 변경 → `search` state 갱신 **+ 즉시 `selected` 초기화**(원본 JSX 그대로: `onChange={e=>{setSearch(...);setSelected(null);}}`). 디바운스 후 서버 재조회(`GET /books/search?q=`) 권장(추론 — 원본은 mock 즉시 필터링) |
| 초기화 버튼 | 클릭 → 검색어와 선택 상태 모두 초기화. disabled 조건은 미확정(아래 참조) |
| 좌측 표 행 클릭 | 선택 상태 갱신 → 우측 패널이 해당 도서의 상세/소장본 뷰로 전환. 선택된 행의 "도서명" 셀만 강조(semibold + primary색) |
| 좌측 표 로딩 | `DataTable`의 `loading` prop — 첫 로드는 빈 행에 문구, 페이지 이동은 표 흐림(`opacity-60`) |
| 좌측 표 에러 | `ListErrorState`(재시도 버튼) — 표 대신 렌더 |
| 좌측 표 빈 결과 | `emptyText="검색 결과가 없습니다."` |
| 우측 패널(선택 없음) | 중앙 정렬 placeholder 텍스트, 상호작용 없음 |
| 우측 패널(선택 있음, 로딩) | 상세 조회(`GET /books/{id}`) 진행 중 — 표시 방식 미확정(아래 참조) |
| 우측 패널(선택 있음, 에러) | 404 등 조회 실패 시 UX 미확정(아래 참조) |
| 우측 표 빈 소장본 | `emptyText="등록된 소장본이 없습니다."` |
| 우측 표 상태 배지 | `StatusBadge status={row.status}` — hover/focus 없음(정적 배지) |
| DataTable 행(클릭 가능) | 이미 `hover:bg-surface-muted` + `focus-ring` + 키보드 조작(Enter/Space) 내장 — 별도 구현 불필요 |
| 페이지네이션 | 좌측 결과: 서버/클라이언트 모드 미확정(아래 참조). 우측 소장본: 원본에 없음 — 전체 표시 |

## 반응형 규칙

- 검색바 Card: `flex` row, `gap-2.5`. 원본에 브레이크포인트 분기 명시 없음. `LoanHistoryCard`
  선례(`flex-col gap-2.5 sm:flex-row sm:items-center` — 모바일 세로 스택 → `sm` 이상 가로)를
  이 화면에도 적용 권장(추론).
- 2단 결과 영역: `flex flex-wrap gap-5`. 좌 `flex-basis: 2 1 520px`, 우 `flex-basis: 1 1 400px`.
  고정 브레이크포인트가 아니라 **콘텐츠 폭 기반 자연 wrap**이다 — 컨테이너 폭이
  두 카드의 최소 폭 합(약 520+400+20=940px) 아래로 좁아지면 우측 카드가 다음 줄로 내려가
  세로 스택된다. 명시적 `sm`/`md`/`lg` 오버라이드는 원본에 없음 — 그대로 유지 권장.
- MetaRow(저자/출판사/ISBN): `flex flex-wrap gap-5` — 이미 wrap 지원, 좁은 화면에서 자동
  줄바꿈.
- 페이지 좌우/상하 여백은 `layout.tsx`의 `<main>`이 소유 — 이 화면에서 별도 반응형 처리 불필요.

## 미확정 항목

1. **SearchInput 아이콘 삽입 방식.** `Input`에 leading icon prop을 확장할지, 화면/도메인
   레이어에서 relative+absolute 조합으로 처리할지 component-architect 판단 필요.
2. **좌측 "소장본" 컬럼 표시 포맷.** 원본 문자 그대로 단위를 살려 `"{n}권"`으로 표시할지,
   기존 `BookListCard`의 "소장본 수" 컬럼처럼 순수 숫자만 표시할지 확인 필요 — 두 화면의 컬럼
   정의를 `book-table.ts`로 합칠 경우 포맷이 일치해야 한다.
3. **우측 2컬럼 표(관리번호/상태) 너비 비율.** 원본 4컬럼 폭(32/24/22/22%)을 2컬럼으로 재분배할
   정확한 비율이 미확정 — 잠정 제안 "관리번호 60% / 상태 40%"(관리번호 `nowrap` 고려), 최종은
   구현 시 조정 가능.
4. **초기화 버튼 disabled 조건.** 원본은 항상 활성이나 `LoanHistoryCard` 선례는
   `disabled={!hasFilter}` — 통일 여부 확인 필요.
5. **좌측 표 페이지네이션 모드.** 원본은 `pageSize=10`(클라이언트 모드, mock 데이터 특성상)이나
   실제로는 서버 페이지네이션 API(`searchBooks`)를 쓰므로 `BookListCard` 선례처럼
   `serverPagination`을 권장 — 최종 결정은 architect/implementer 확인 필요.
6. **행 클릭 시 `GET /books/{id}` 실패(404/네트워크 오류) UX.** design-source가 "`ListErrorState`
   패턴(재시도)로 처리 검토"라고만 남겨둠 — 우측 카드 내부에 `ListErrorState`를 표시할지, 다른
   처리(Toast 등)를 할지 확인 필요. 상세 로딩 중 표시(스피너/스켈레톤 여부)도 동일하게 미확정.
7. **nav 항목 삽입 위치(순서).** "도서 등록" 바로 다음이 자연스러워 보이나 확정 아님.
8. **`IconSearch` 좌표계.** 원본 `SearchSvg`는 16×16 좌표계(circle r=5 center 7,7 / path
   11.5,11.5→14,14)인데, 기존 사이드바 아이콘들(`IconBook` 등)은 20×20 좌표계다. 두 가지 선택지:
   (a) `Toast` 알림 아이콘들(`IconCheckCircle` 등)의 `SizedIconProps` 패턴처럼
   `viewBox="0 0 16 16"`을 고정 오버라이드해 원본 좌표를 그대로 쓰거나, (b) 다른 nav 아이콘과
   시각적 비중을 맞추기 위해 좌표를 20×20 기준으로 1.25배 리스케일. 시각적 일관성 확인 필요.
9. **상세 조회 시점.** `selected`가 바뀔 때마다 매번 `getBook()`을 재호출할지, 이미 조회한
   도서를 캐시할지(예: 같은 행을 다시 클릭) 미확정 — 원본엔 이런 개념 자체가 없음(mock 데이터라
   조회 비용이 0).
