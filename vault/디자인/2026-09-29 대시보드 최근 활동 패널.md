## 개요

`#37`에서 만든 대시보드 "최근 대출 활동" 카드는 `SearchLoansService.LoanSummary`를 대여일(`loanDate`) 내림차순으로 받아 그렸다. 백엔드가 이번에 `/dashboard/summary`를 "최근 활동" 조회로 바꾸면서(대출·반납을 모두 포함, `updatedAt desc, id desc` = 활동 발생 시각 내림차순), 응답 필드가 `recentLoans → recentActivities`(타입도 `LoanSummary[] → LoanActivity[]`)로, 카드가 보여줄 것도 "대여 시각"에서 "활동(대출 또는 반납) 시각"으로 바뀐다. 화면 변경은 API 배선 갱신 + 컬럼 구성 변경(대여일 컬럼 삭제, 상대 시간 컬럼 신규) + 카드 제목/캡션 문구 변경이 전부다. KPI 4장, 연체 목록 패널, 2:1 그리드 레이아웃은 이번 스코프 밖이며 변경하지 않는다.

반복 패턴 강조(component-architect 참고):
- **컬럼 정의 반복**: `LOAN_COLUMN_DEFS`(`loan-table.ts`)가 이미 "키 → {label, secondary, nowrap} 단일 진실 원천 + 폭 주입 함수" 패턴으로 3개 컬럼셋(`LOAN_COLUMNS`/`LOAN_HISTORY_COLUMNS`/`DASHBOARD_LOAN_COLUMNS`)을 만들어냈다. 이번 변경은 **행 타입이 처음으로 갈라지는 지점**이다 — `LOAN_COLUMN_DEFS`는 `Record<string, ... satisfies Omit<DataTableColumn<LoanSummary>, ...>>`로 `LoanSummary` 키에 고정돼 있어, `LoanActivity` 전용 컬럼(`activityAt`)을 넣으려면 이 상수의 타입을 넓히거나 별도 정의를 둬야 한다. 이 결정은 스펙 범위가 아니라 architect 판단 사항으로 넘긴다.
- **배지 라벨 오버라이드 반복**: `StatusBadge`에 `label` prop으로 오버라이드하는 사용처가 늘어난다(현재 0곳 → 이 카드 1곳). 반복 임계치(2회) 미달이라 신규 공통 컴포넌트가 필요하진 않지만, "이 카드 전용 로직"이라는 위치(어디서 오버라이드를 계산할지 — 렌더 함수 내 인라인 vs `loan-table.ts`의 헬퍼)는 architect가 정할 것.
- **상대 시간 포맷은 이 화면에서 처음 등장** — 반복은 없지만(단일 사용처), `dday.ts`처럼 "순수 함수 + 별도 파일" 패턴을 그대로 따라야 향후 재사용(예: 다른 화면에 활동 로그가 생길 경우) 가능하다.

## 컬럼 구성 (5컬럼, 폭 비율)

디자인 원본 폭(도서명 30% / 대출자 12% / 부서 16% / 활동 14% / 시간 14%, 합 86% — 목업 오차)의 **비율**을 유지하며, 기존 `DASHBOARD_LOAN_COLUMNS`처럼 합계 100%로 정규화하는 것을 권장한다(정확한 정규화 값 산출은 architect/implementer 재량 — 이 스펙은 비율 의도만 확정한다).

| 순서 | key | 라벨 | 원본 폭(비정규화) | secondary | nowrap | 비고 |
|------|-----|------|-------------------|-----------|--------|------|
| 1 | `bookTitle` | 도서명 | 30% | 아니오 | 아니오 | 기존과 동일 |
| 2 | `borrowerName` | 대출자 | 12% | 아니오 | 아니오 | 반납 건은 `EmptyCell`로 렌더(아래 참고) |
| 3 | `department` | 부서 | 16% | 예 | 아니오(디자인에 `nowrap` 명시 없음) | 기존과 동일 |
| 4 | `status` | 활동 | 14% | 아니오 | 아니오 | 배지. 반납 건은 라벨 "반납" 오버라이드 |
| 5 | `activityAt` | *(빈 문자열)* | 14% | 예 | 예 | `DataTableColumn.label`은 필수 `string` 타입이라 `""`을 넣으면 타입상 문제없이 헤더가 빈 칸으로 렌더된다 — "라벨이 optional"이 아니라 "빈 문자열 값"임에 주의 |

**삭제되는 컬럼**: `loanDate`(대여일). API 응답에는 `loanDate` 필드가 여전히 존재하지만(백엔드 스펙 변경 문서 확인), 이 카드의 표시 요구사항에서만 제외한다 — 데이터 삭제가 아니라 화면 표시 범위 축소다.

**여전히 없는 컬럼**(기존과 동일, 변경 없음): 관리번호, 반납예정일, 반납일 — 2단 좁은 패널 제약으로 원래부터 제외돼 있었다.

## 상대 시간 규칙 (`activityAt` → 표시 텍스트)

입력: `activityAt: string` — ISO-8601 문자열(예: `"2026-09-13T14:05:00"`), 백엔드 `LocalDateTime`을 Jackson이 직렬화한 값. 기존 `client.ts`의 날짜/시각 파싱 관례를 따른다(별도 커스텀 파서 불필요 — `new Date(isoString)`로 파싱 가능).

기준 시각을 `now`(호출 시점)라 할 때, 경과 분(`mins`)·시간(`hrs`)·일(`days`)로 계산해 아래 규칙을 **순서대로** 적용한다:

| 조건 | 표시 |
|------|------|
| `mins < 1` | "방금 전" |
| `mins < 60` | `"{mins}분 전"` |
| `hrs < 24` | `"{hrs}시간 전"` |
| `days === 1` | "어제" |
| `days < 7` | `"{days}일 전"` |
| `days < 28` | `"{Math.floor(days/7)}주 전"` |
| 그 외(28일 이상) | 날짜 표기(`activityAt`의 날짜 부분, `YYYY-MM-DD`) |

부가 규칙:
- 셀에는 `title` 속성(툴팁)으로 원본 `activityAt` 값을 노출한다 — 접근성/정확도 보완 목적이므로 구현 시 유지를 권장(디자인 원본에도 있음).
- 디자인 원본의 `timeAgo(at)`는 `at.length > 10`이면 `new Date(at)`, 아니면 날짜만 있는 값으로 가정해 `'T09:00:00'`을 붙였다 — 이는 **디자인 목업이 날짜 전용 더미 데이터를 다뤘기 때문에 생긴 방어 코드**로 추정된다(미확정 — 원본 프로젝트에 이 분기가 왜 필요했는지 확인되지 않음). 실제 API는 항상 완전한 `LocalDateTime` ISO 문자열을 내려주므로(백엔드 스펙 확인됨), **이 길이 분기는 이식하지 않아도 될 가능성이 높다** — 다만 구현자가 신규 유틸을 만들 때 최종 판단.
- "지금"의 기준(요청 시점 vs 렌더 시점, 클라이언트 vs 서버 계산)은 미확정 — 아래 미확정 항목 참고.

## 상태 & 상호작용

| 요소 | 상태/동작 |
|------|-----------|
| `status` 컬럼 — 대출 중 건(`status="ON_LOAN"`) | 기존 `toLoanBadgeStatus(row)` 로직 그대로 재사용 — `overdue=true`면 "연체"(danger), 아니면 "대출중"(warning). 라벨 오버라이드 없음 |

| `borrowerName` 컬럼 — 대출 중 건 | 값 그대로 렌더(변경 없음) |
| `activityAt` 컬럼 | 클릭/hover 인터랙션 없음(정적 텍스트 + `title` 툴팁). hover/focus 상태 별도 없음 |
| 카드 전체 — 로딩 | `DashboardSection`이 내리는 `loading` prop을 `DataTable`에 그대로 전달(기존과 동일 — 카드 단위 로딩 아님, 화면 단위) |
| 카드 전체 — 빈 상태 | `emptyText` 문구 갱신 필요 여부 미확정(현재 "아직 대출 기록이 없습니다." — "활동"으로 바뀌었으니 "아직 활동 기록이 없습니다." 등으로 조정할지는 문구 담당 판단. 아래 미확정 항목 참고) |
| 행 클릭 | 기존과 동일하게 없음(`onRowClick` 미지정) — 변경 없음 |

## 반응형 규칙

이번 변경으로 반응형 동작은 바뀌지 않는다(스코프 아님). 참고로 기존 레이아웃 규칙만 재확인:
- base: `DataTable`은 `overflow-x-auto` 컨테이너로 감싸여 있어 좁은 화면에서 가로 스크롤됨(기존 동작 유지).

- KPI 그리드: `auto-fit minmax(220px,1fr)` — 변경 없음.

## 데이터/콘텐츠 형태

### 신규 타입: `LoanActivity` (`lib/api/loans.ts` 소유 권장 — `OverdueLoanSummary` 선례를 따름, `dashboard.ts`가 import)

```ts
export type LoanActivity = {
  loanId: number;
  managementNumber: string;
  bookTitle: string;
  /** 반납 완료 건은 개인정보 파기로 null (LoanSummary.borrowerName과 동일 규칙) */
  borrowerName: string | null;
  department: string;
  /** LocalDate "YYYY-MM-DD" — 응답에는 존재하지만 이 카드는 표시하지 않는다 */
  loanDate: string;
  /** LocalDate "YYYY-MM-DD" */
  dueDate: string;
  /** LocalDate "YYYY-MM-DD" — 미반납이면 null */
  returnedAt: string | null;
  status: LoanStatus; // "ON_LOAN" | "RETURNED" — 기존 타입 재사용
  overdue: boolean;
  /** LocalDateTime ISO-8601 문자열 — 대출 또는 반납이 발생한 시각. 상대 시간 표시 기준 */
  activityAt: string;
};
```

- `interface`가 아니라 `type`으로 선언 필요(`DataTable<T extends Record<string, unknown>>` 제약 — `LoanSummary`/`OverdueLoanSummary`와 동일한 이유, 기존 코드 주석에 명시됨).
- `LoanSummary`와 필드가 거의 동일하고 `activityAt`만 추가된 형태이지만, 서버가 별개 타입(`RecentLoanActivitiesService.LoanActivity`)으로 내려주므로 `LoanSummary`에서 파생시키지 않는 것을 권장(기존 `OverdueLoanSummary`가 `LoanSummary`와 별개로 선언된 전례와 일관).

### `DashboardSummary` 변경 (`lib/api/dashboard.ts`)

```ts
export type DashboardSummary = {
  bookCount: number;
  bookItemCount: number;
  availableBookItemCount: number;
  activeLoanCount: number;
  overdueLoanCount: number;

```

- 쿼리 파라미터: `recentLoanLimit` → `recentActivityLimit` (기본값 10 동일, 상수명 `RECENT_LOAN_LIMIT`을 그대로 둘지 `RECENT_ACTIVITY_LIMIT`로 바꿀지는 architect/implementer 판단 — 백엔드 캐시 키(`@Cacheable`)가 파라미터 이름에 의존하므로 **쿼리 스트링 키 값 자체는 반드시 `recentActivityLimit`로 보내야 한다**).
- `RecentLoansCardProps.rows: LoanSummary[]` → `LoanActivity[]`.

## 미확정 항목 (확인 필요)

1. **`DataTable caption`/`emptyText`/JSDoc의 정확한 최종 한국어 문구.** 방향(활동 시각 최신순 등)은 확정됐지만 토씨 하나까지 확정된 텍스트는 디자인 원문에 없다 — 구현 시 자연스러운 한국어로 확정, 필요하면 사용자 확인.
2. **상대 시간 계산의 "현재 시각" 기준.** 컴포넌트 렌더 시점마다 재계산하는지(예: `Date.now()`를 매 렌더 호출), 아니면 일정 주기로 갱신(예: setInterval로 1분마다 리렌더)하는지 디자인 원문(`const NOW`가 모듈 스코프 상수처럼 보임)과 백엔드 문서 모두 명시하지 않음 — "방금 전"이 시간이 지나도 안 바뀌는 문제가 생길 수 있음. UX 요구사항 확인 필요.
3. **디자인 원본의 `timeAgo` 날짜-전용 입력 분기(`at.length > 10` 체크, `'T09:00:00'` 보정)를 실제 유틸에도 이식할지.** 실제 API는 항상 완전한 ISO `LocalDateTime` 문자열을 내려주므로 불필요해 보이지만, 디자인 의도(예: 다른 화면에서 날짜 전용 값도 같은 유틸에 넣을 가능성)를 배제할 수 없어 확정하지 않음.
4. **`RecentLoansCard` 컴포넌트/파일명을 "최근 활동" 개명에 맞춰 리네이밍할지.** 이번 변경은 최소한 prop 타입과 표시 문구만 바꾸면 기능적으로 충분하지만, 이름이 실제 역할과 계속 어긋나는 것을 감수할지는 architect/팀 컨벤션 판단 사항.
5. **`RECENT_LOAN_LIMIT` 상수명 리네이밍 여부.** 쿼리 파라미터 키(`recentActivityLimit`)는 백엔드 캐시 키와 직결되어 반드시 바꿔야 하지만, 프론트 상수 변수명 자체는 기능에 영향 없어 리네이밍이 선택 사항 — 코드 일관성 관점에서는 맞추는 편이 자연스러움.
6. **`department` 컬럼의 `nowrap` 여부.** 디자인 원문 `cols` 배열에 `dept`는 `secondary:true`만 있고 `nowrap`은 없음(원본 `_at` 컬럼에만 `nowrap:true`). 기존 `LOAN_COLUMN_DEFS.department`도 `nowrap` 없이 `secondary`만 있어 일치하지만, 재검토 시 그대로 유지할지 재확인.
