**1. API 계층** (`015a368`)
- `lib/api/dashboard.ts` 신규 — 백엔드에 **화면 전용 집계 엔드포인트**(`GET /dashboard/summary`)가 이미 있어 **호출 한 번**으로 화면 전체를 채웁니다. `/books`·`/bookitems`·`/loans`를 따로 긁지 않습니다(호출이 4~5개로 늘고 집계 기준일이 갈라집니다).
- 표시 건수는 모듈 상수 — 서버가 limit 조합을 `@Cacheable` 키로 쓰기 때문입니다.
- `OverdueLoanSummary` 타입은 `loans.ts`(도메인)가 소유하고 `dashboard.ts`가 임포트합니다.
- 🐛 **`LoanSummary.borrowerName`을 nullable로 교정**했습니다. 서버는 반납 시점에 대출자 이름을 파기해 `null`을 내려주는데 프론트 타입이 이를 감추고 있었습니다.

**2. 중복 제거 리팩터** (`cd205b4`)
- `loan-table.ts`가 예고했던 조건(셋째 컬럼셋)이 충족돼 **공통 정의 + 폭 주입**으로 리팩터했습니다. `label`/`secondary`/`nowrap`이 한 곳에만 남아 "표마다 라벨이 갈라진다"는 실패 모드가 구조적으로 불가능해졌습니다. **기존 export 이름·값은 그대로**라 소비자 3곳은 무수정입니다.
- `loan-history-card`의 인라인 플레이스홀더를 `ui/EmptyCell`로 승격(두 번째 사용처 발생).
- 위 타입 교정 덕에 대출 내역 화면의 기존 결함(반납 완료 건 대출자 셀이 빈 칸)도 함께 고쳤습니다.

**3. 화면** (`e763218`)
