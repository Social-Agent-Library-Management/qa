## 연관 이슈
- 이 PR이 해결하는 이슈: #9

## 작업 사항
- `lib/api/bookitems.ts`: 백엔드 `bookitem` 도메인(`POST /books/{bookId}/bookitems`) 연동 레이어 추가
- `ui/Field` 추출: `Input`의 라벨/hint/error 껍데기를 분리(공개 API·렌더 결과 불변, `/books/new` 회귀 없음)
- `ui/Combobox` 신규: 도메인 지식 없는 제네릭 검색-선택 리스트박스(키보드/ARIA 포함). 선택 상태에서 타이핑 시 항상 `onChange(null)`이 먼저 호출되는 불변식으로 "화면 텍스트 ↔ 선택값" 불일치를 구조적으로 차단
- `library/BookSelectField` 신규: `Combobox` + `searchBooks`(디바운스 250ms, 요청 취소) 배선
- `library/CopyRegisterForm` + `/copies/new` 페이지: 도서 검색·선택 + 관리번호 입력으로 소장본을 등록. 서버 에러(`INVALID_MANAGEMENT_NUMBER_FORMAT`/`DUPLICATE_MANAGEMENT_NUMBER`/`BOOK_NOT_FOUND`)를 필드별로 매핑
- `src/components/README.md` 컴포넌트 인벤토리·합성 관계 갱신

## 범위 관련 참고
디자인 목업에는 소장본 목록 테이블(검색·상태배지·분실/폐기)이 있으나, 백엔드 `bookitem` 도메인에는 목록/검색 조회 API가 없어(등록·상태변경만 존재) 사용자 확인 후 이번 범위에서는 **등록 폼만** 구현했습니다. 목록 조회는 백엔드 API가 추가되면 후속 이슈로 진행합니다.

- `ui/Combobox`는 향후 `/loans/new`(대출 등록)의 소장본·회원 선택에서도 재사용할 것을 염두에 두고 도메인 지식 없이 설계했습니다.
- 검증 실패 시 안내 문구가 포커스로 열린 드롭다운에 가려질 수 있는 UX 이슈를 인지하고 있습니다(기능 결함 아님, 필요 시 후속으로 조정).
