# frontend PR #24 feat(#23): 도서 검색 화면 구현

## 증상·요구 (연결 이슈)
### 이슈 #23 feat: 도서 검색 화면 구현
## 구현 계획
- 디자인: Claude Design `ui_kits/library/index.html`의 `BookSearchScreen`(id `book-search`) 반영
  - 검색창(도서명·저자·출판사·ISBN) + 검색 결과 표 + 선택 시 우측 소장본 패널 2단 레이아웃
  - 검색 결과 표: `GET /books/search?q=` 재사용(`searchBooks`)
  - 우측 소장본 패널: `GET /books/{id}` 신규 연동(`GetBookService` — 도서 상세 + 소장본 목록)
- **제약**: 도서 단건 조회 응답의 소장본 목록(`bookItems`)에는 `대출자`/`반납예정일` 필드가 없음(백엔드 `GetBookService.BookItemSummary`는 `bookItemId`/`managementNumber`/`status`/`createdAt`만 보유). 디자인 원본은 이 두 컬럼을 포함하지만 **API에 없는 데이터이므로 UI에서 제외**하고 관리번호·상태 2컬럼으로 구현한다.
- 검색 결과의 "대출가능 n" 표기도 동일한 이유로 제외(백엔드 검색 응답엔 상태별 세부 카운트 없이 `bookItemCount` 총계만 있음) — 총 소장본 수만 표시.
- 사이드바 내비게이션에 "도서 검색" 항목 추가, 라우트 `/books/search`.
- 재사용: `Card`/`Input`/`Button`/`DataTable`/`StatusBadge`/`Badge`/`AppSidebar` 등 기존 `src/components` 컴포넌트 우선 검토.

## 작업 사항
- Claude Design `ui_kits/library/index.html`의 `BookSearchScreen`을 기반으로 도서 검색 화면(`/books/search`) 구현
- 검색바(도서명·저자·출판사·ISBN, 디바운스) + 좌측 검색 결과 표 + 우측 소장본 상세 2단 레이아웃
- `GET /books/{id}` 신규 연동(`getBook()` + `BookDetail`/`BookItemSummary` 타입)
- **제약 반영**: 백엔드 도서 단건 조회 응답(`GetBookService.BookItemSummary`)에 대출자·반납예정일 필드가 없어, 우측 소장본 표는 디자인 원본의 4컬럼이 아니라 **관리번호·상태 2컬럼만** 구현. 좌측 검색 결과의 소장본 컬럼도 "대출가능 n" 표기 없이 **총 소장본 수만** 표시(백엔드 검색 응답에 상태별 세부 카운트 없음)
- 재사용: `Card`/`DataTable`/`Badge`/`StatusBadge`/`Button`/`PageHeader`/`ListErrorState`/`AppSidebar` 등 기존 컴포넌트 그대로 사용
- 신규: `Input`에 `leadingIcon` prop 확장, `IconSearch` 아이콘, 사이드바 "도서 검색" 내비게이션 항목
- 중복 제거: `BookListCard`와 신규 `BookSearchResultCard`가 쓰는 도서 컬럼 정의(`BOOK_COLUMNS`)를 `book-table.ts`로 분리해 공유(`loan-table.ts` 선례와 동일 원칙)
