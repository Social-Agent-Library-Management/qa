# frontend PR #26 feat(#25): 소장본 등록 화면에 소장본 목록·상태 변경 구현

## 증상·요구 (연결 이슈)
### 이슈 #25 feat: 소장본 등록 화면에 소장본 목록·상태 변경 구현
## 구현 계획
- `/copies/new` 화면에 소장본 목록 카드 추가 (`GET /bookitems` 검색 API 연동, q/managementNumber 두 입력, 서버 페이지네이션)
- 상태별 상태 변경 액션 열: AVAILABLE → 분실/폐기 버튼, ON_LOAN → "대출 중 변경 불가", LOST/DISPOSED → "—"
- `PATCH /bookitems/{bookItemId}/status` 연동 (LOST/DISPOSED만 허용, 성공 시 재조회)
- 기존 `CopyRegisterForm`과 조합하는 `CopyRegisterSection`(refreshToken 배선) 신설, 페이지는 조립만
- 재사용: `Card`/`Input`/`Button`/`DataTable`/`StatusBadge`/`Toast`/`ListErrorState` — 신규 프리미티브 없음

## 변경 내용 (PR 본문)
## 연관 이슈
- 이 PR이 해결하는 이슈: #25

## 작업 사항
- `GET /bookitems`(관리번호·도서명 검색, 서버 페이지네이션), `PATCH /bookitems/{id}/status`(분실·폐기) 연동 함수·타입 추가 (`src/lib/api/bookitems.ts`)
- `BOOK_ITEM_NOT_FOUND_CODE` 중복 선언 방지 — 소유권을 `bookitems.ts`로 옮기고 `loans.ts`는 재수출만 유지
- `CopyListCard` 신규: 소장본 목록 + 검색(관리번호/도서명 입력 2개, AND) + 상태별 3분기 액션(AVAILABLE→분실/폐기 버튼, ON_LOAN→변경 불가 문구, LOST/DISPOSED→종결 표시)
- 상태 변경 성공 시 낙관적 갱신 없이 재조회(`fetchToken`), 등록 성공 시 별도 트리거(`refreshToken`)로 1페이지 리셋 — 두 트리거를 의도적으로 분리해 상태 변경할 때마다 목록이 1페이지로 튀지 않게 함
- `CopyRegisterForm`에 `onCreated` 콜백 추가, `CopyRegisterSection` 신설로 폼·목록 배선을 페이지에서 분리
- `src/components/README.md` 컴포넌트 인벤토리·합성 관계 동기화 (Combobox 문단의 낡은 서술도 정정)

## 디자인 대비 변경 사항 (사용자 확인 완료)
- 백엔드 검색 응답에 `bookTitle`이 없던 초기 상태를 확인해 사용자가 백엔드에 필드를 추가함(재확인 완료)
- 디자인 원본의 통합 검색창 1개는 백엔드 `q`/`managementNumber`가 AND 조건이라 그대로 구현 불가 — 사용자 확인 후 입력 2개(관리번호/도서명)로 대체
