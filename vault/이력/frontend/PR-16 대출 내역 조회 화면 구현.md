## 구현 계획
- `/loans/history` 화면(현재 PagePlaceholder)을 실제 대출 내역 조회 화면으로 구현
- GET /loans (bookTitle/borrowerName/department/status 서버 필터 + 서버 페이지네이션) 연동
- 기존 `LoanListCard`/`ReturnListCard` 패턴 재사용, `DataTable`의 serverPagination 사용
- 디자인 원본의 통합 검색창/연체 상태 필터는 백엔드가 지원하지 않아(관리번호 필터 없음, overdue는 상태값이 아닌 파생 필드) 컴포넌트 설계 단계에서 필터 UI를 서버 파라미터에 맞게 재구성

## 작업 사항
- `GET /loans`에 `bookTitle`/`borrowerName`/`department` 서버 필터 파라미터 추가 (`lib/api/loans.ts`)
- `LoanListCard`/`ReturnListCard`에 중복돼 있던 컬럼 정의·상태 배지 매핑을 `library/loan-table.ts`로, `book-select-field.tsx`에 인라인돼 있던 디바운스를 `lib/use-debounced-value.ts`로 추출·공용화
- `/loans/history`의 `PagePlaceholder`를 실제 화면(`LoanHistoryCard`)으로 교체: 도서명/대출자/부서 개별 입력(250ms 디바운스) + 상태 select(전체/대출중/반납완료) + 서버 페이지네이션
- 신규 재사용 컴포넌트를 `src/components/README.md` 인벤토리·합성 관계 표에 반영

## 설계 결정 (디자인 원본과 다른 점)
- 디자인 원본은 통합 검색창 1개(도서명·대출자·관리번호)지만, 백엔드 `GET /loans`는 관리번호 필터가 없고 bookTitle/borrowerName/department가 서로 다른 파라미터라 "한 문자열을 여러 필드에 OR로" 서버 필터링할 방법이 없다 → **도서명/대출자/부서 개별 입력 3개(AND 조합)**로 재구성했다.
- 디자인 원본은 상태 select에 "연체" 옵션이 있지만, 서버 `status`는 `ON_LOAN`/`RETURNED` 두 값뿐이고 연체는 행별 파생 불리언(`overdue`)이라 서버로 필터링할 수 없다 → **"연체" 옵션을 드롭**하고 전체/대출중/반납완료 3옵션으로 축소했다. 연체 배지 자체는 행에 계속 노출된다.
- 이 화면은 반납 완료 건까지 포함한 전체 이력이라 데이터가 계속 늘어나므로, `ReturnListCard`의 fetch-all + 클라이언트 필터 패턴 대신 `LoanListCard`와 동일한 진짜 서버 페이지네이션(`DataTable`의 `serverPagination`)을 사용했다.
