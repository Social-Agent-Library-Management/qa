# frontend PR #44 fix(#43): 도서 검색창 문구·오타 제안 배너 게이팅 수정

## 증상·요구 (연결 이슈)
### 이슈 #43 fix: 도서 검색 페이지 검색창 문구·오타 제안 배너 수정
## 문제 상황(배경)
도서 검색 화면(`/books/search`)에 두 가지 문제가 있었다.

1. 검색창 placeholder/aria-label이 "도서명, 저자, 출판사, ISBN 검색"이었지만, 백엔드(`BookRepository.searchActive`, OpenSearch 어댑터 모두)는 실제로 제목·저자만 매칭한다. 출판사·ISBN은 검색 대상이 아닌데 문구가 과장돼 있었다. Claude Design의 `BookSearchScreen`도 "도서명, 저자 검색"으로 되어 있다.
2. `GET /books/search` 응답의 `suggestion`(오타 교정 제안, 예: "나무와숲")은 서버가 "결과 건수와 무관하게" 내려주는데(`SearchBooksService.Response` 코멘트, `exactSubstringHits == 0`), 프론트는 이 배너를 `DataTable`의 `emptyText` 슬롯 안에 넣어놔서 사실상 "현재 페이지 결과가 0건일 때만" 뜨는 숨은 게이트가 있었다. 검색 결과가 있어도 오타 제안이 함께 와야 하는 경우를 놓치고 있었다.

## 해결 방안(구현 계획)
- 검색창 placeholder/aria-label을 "도서명, 저자 검색"으로 수정
- 오타 제안 배너를 `DataTable` 밖으로 꺼내 독립 렌더하고, 트리거를 `suggestion !== null` 하나로 단순화(`totalElements`/`rows.length` 게이팅 제거)
- Claude Design 최신 배치(검색바 카드 안, 입력 아래, 구분선 없음)에 맞춰 배너 위치·스타일 조정 — `BookSearchResultCard`가 파생값(`SuggestionInfo`)만 계산해 `BookSearchSection`에 올리고, 실제 렌더는 `BookSearchSection`이 검색바 카드 안에서 담당

## 작업 사항
