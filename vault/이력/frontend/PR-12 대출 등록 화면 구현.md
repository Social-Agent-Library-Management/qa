## 작업 사항
- `src/lib/api/loans.ts`: POST /loans(대출 등록), GET /loans(대출 목록 검색) 연동 레이어 추가. 공통 `PaginationMeta`는 `client.ts`로 승격해 `books.ts`와의 중복 정의 제거(기존 임포트 경로는 재수출로 유지)
- `LoanRegisterForm`: 관리번호·대출자 이름·부서명·대여일 입력 + 반납예정일(+14일) 실시간 미리보기. 관리번호는 백엔드에 검색/목록 API가 없어(`findByManagementNumber` 단건 조회만 존재) `Combobox` 대신 plain `Input` + 서버 에러 코드(`BOOK_ITEM_NOT_FOUND`/`BOOK_ITEM_NOT_AVAILABLE`) 필드 에러로 처리
- `LoanListCard`: 현재 대출 현황(`status=ON_LOAN`) 서버 페이지네이션 목록. 연체 뱃지는 서버가 계산한 `overdue`를 그대로 사용(프론트 재계산 없음)
- `LoanRegisterSection`: 폼·목록 사이 `refreshToken` 배선(`BookRegisterSection`과 동일 패턴)
- `src/app/loans/new/page.tsx`: 기존 `PagePlaceholder`를 실제 화면으로 교체 (서버 컴포넌트 유지, `metadata` export 보존)
- `src/components/README.md`: 컴포넌트 인벤토리·합성 관계 갱신, 기존에 잘못 적혀 있던 "관리번호는 Combobox 경로를 쓴다" 예측 문장을 실제 API 조사 결과로 정정

디자인은 Claude Design `ui_kits/library/index.html`의 `LoanRegistrationScreen`을 그대로 따랐고("초기화" 버튼만 자매 폼 컨벤션에 맞춰 전체 필드 리셋으로 통일), API 계약은 백엔드 Kotlin(`org.library.loan`, `org.library.bookitem`)을 직접 읽어 확인했습니다.

신규 `ui/` 프리미티브·variant는 없습니다(기존 Card/Input/Button/DataTable/Toast/StatusBadge 재사용).
